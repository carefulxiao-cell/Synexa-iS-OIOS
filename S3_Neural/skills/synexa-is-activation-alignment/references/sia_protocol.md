# Synexa iS Activation & Alignment Protocol v0.1

## Short name

SIA = Synexa iS Activation & Alignment｜超智 iS 激活与对齐协议。

## One-line definition

SIA is the global activation and alignment protocol for turning a complex task into a Task Room, composing capability domains, foundation skills, project/theme skills, execution agents, and asset governance into one working loop.

## Trigger modes

### SIA-Start｜任务激活

Trigger: `启动 SIA`

Purpose: convert a request into a Task Room.

Required output:
- Mission Brief
- Task level
- Owner / main role
- Expert Pod
- Professional Pod
- Capability Domains
- Foundation Skills
- Project / Theme Skills
- Execution Agents
- Asset Destination

### SIA-Work｜同框协同

Trigger: `按 SIA 执行`

Purpose: complete multi-domain work in the current conversation.

Required output:
- SCO perspective
- Matrix perspective
- Hub perspective if external scan is needed
- PCS perspective if project execution is needed
- Core escalation check
- Execution package
- Validation criteria
- Return feedback requirement

### SIA-Audit｜巡检对齐

Trigger: `启动 SIA 巡检`

Purpose: inspect files, data sources, skills, versions, GitHub state, and baseline conflicts.

Required output:
- Active files
- Outdated files
- Misplaced files
- Conflict risks
- Required updates
- Upload/remove suggestions
- Manus repair package if needed

### SIA-Release｜发布校准

Trigger: `启动 SIA 发布检查`

Purpose: check readiness before releasing a skill, SOP, protocol, capability pack, or repository update.

Required output:
- Version check
- File list
- Naming check
- Dependency check
- Test cases
- Whether Core is needed
- Whether the package can go to Manus

## Default principle

SIA is not only an audit tool. It is the activation key for Synexa iS all-domain collaboration. Audit is one mode.
