# SOP-007: 指令汇总追踪表机制标准规范 (Instruction Tracker Standard)

> **版本**：v1.1
> **生效日期**：2026-04-20
> **适用范围**：Synexa iS 体系下所有 PCS 工作空间及治理工作空间
> **维护主体**：iS-Core (智核中枢)

---

## 1. 机制定位与背景

「指令汇总追踪表」机制最初在 iS-NexFlow PCS 空间进行多轮迭代验证，有效支撑了策略室（SCO）与执行框（PCS）的协作闭环。为解决「指令已下发但执行框未按标准格式反馈」「生产验证缺失」等问题，iS-Core 正式裁决将此机制提升为体系级标准，写入 OIOS 基线，供所有工作空间统一遵循。

本机制旨在确保：**指令不遗漏、状态可追溯、废弃无歧义、全局可监控**。

**执行主体定义**：每个项目/系统必须设立专属的「中枢-xxxx」对话组（或角色），作为该项目的指令治理入口，负责严格执行本规范。

---

## 2. 追踪表标准结构

每个工作空间必须在其对应的 `06-isync/` 目录下（或项目专属文档目录下）维护一个名为 `INSTRUCTION_TRACKER.md` 的文件。

### 2.1 标准字段定义

指令追踪表必须包含以下标准字段：

| 字段名 | 说明 |
| :--- | :--- |
| **编号** | 指令的唯一标识符（如 `CORE-CMD-001`、`NEX-CMD-012`） |
| **描述** | 指令的核心任务或目标一句话概括 |
| **优先级** | P0（最高/阻断性） / P1（高） / P2（中） / P3（低） |
| **批次** | 指令所属的执行批次（如 `B1`、`B2`） |
| **状态** | 当前指令的执行状态（见 2.2 状态枚举） |
| **核心设计共识** | 指令背后的核心逻辑、裁决结果或关键约束 |
| **备注** | 补充说明、依赖关系或异常记录 |

### 2.2 状态枚举定义

指令状态必须严格使用以下枚举值及对应 Emoji：

*   ✅ **已完成**：执行框已完成代码提交，且通过 SCO 核查（含 TBF 验证）。
*   ⏳ **指令已生成待执行框实施**：策略室已输出完整指令包，等待执行框介入。
*   🔲 **待策略室出指令**：任务已规划，但具体执行指令包尚未生成。
*   🚫 **已废弃**：指令因策略变更或被新共识推翻而取消执行。
*   ⚠️ **部分完成/待验收**：执行框已提交部分成果，或已提交但尚未通过 SCO 最终核查。
*   🔒 **依赖锁定**：指令执行被其他前置指令或外部条件阻塞。

## 3. 核心执行规则

### 3.1 批次策略规则

1.  **并行条件**：同一批次内的指令必须满足「文件不冲突、无前后依赖」方可并行下发。
2.  **Schema 变更隔离**：任何涉及数据库结构（Schema）变更的指令，必须单独成批，严禁与其他业务逻辑指令混在一个批次中并行执行。

### 3.2 废弃协议

当旧指令被新共识推翻时，必须严格执行以下三步：
1.  **删除文件**：从代码库或文档库中彻底删除旧指令包文件，不留歧义文档。
2.  **标记状态**：在追踪表中将该指令状态更新为「🚫 已废弃」。
3.  **记录原因**：在追踪表的「已废弃指令」专区记录废弃原因及替代指令编号。

### 3.3 协作约定

**每次策略室（SCO）回复末尾，必须附上最新完整的指令汇总表**。这确保了执行框在任何时候都能看到当前最准确的任务全景，避免上下文断层。

### 3.4 汇总推送规则（FBR 触发协议）

各项目的「中枢-xxxx」在达到里程碑节点或发生重大状态变更时，**不应手动整理内容发送**，而应通过一条简单指令触发 FBR（全局汇聚端）自主读取。

**触发词**：`汇总推送 [项目代号]`

**执行逻辑**：
1. 「中枢-xxxx」发出触发词。
2. FBR 收到指令后，自主前往 GitHub 读取该项目的 `INSTRUCTION_TRACKER.md` 最新文件。
3. FBR 自主对齐状态，并输出全局指令历史与推进排序。

## 4. 经验反哺升级协议（双向同步）

指令汇总机制不仅是自上而下的约束，更是自下而上的进化。

**触发条件**：当「中枢-xxxx」在实战中发现现有 SOP_007 标准存在盲区，或跑出了更高效的指令管理实践时。
**上报格式**：通过 ISYNC 通报向 iS-Core 提交「标准升级建议」，包含：背景 + 建议变更点 + 验证依据。
**裁决流程**：iS-Core 收到通报后，在下一次对话中进行裁决。若通过，则立即升级 SOP_007 并下发全体系。

---

## 5. 全局追踪表映射

各项目的指令摘要将统一汇聚至 `06-isync/GLOBAL_INSTRUCTION_TRACKER.md`，由 Core-FBR 统筹维护，实现跨项目的执行状态监控与风险识别。
