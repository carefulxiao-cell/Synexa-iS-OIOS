## 一、Skill 定位

本 Skill 定义了 Synexa iS 体系内「任务情况汇总」的标准字段规范、双形态输出机制（快照 / 台账）及触发词协议。

**设计原则**：一次定义，全局复用。任何工作空间在系统提示词中引用本文件路径后，即可通过触发词激活标准化的任务汇总能力，无需重复沟通格式与字段。

---

## 二、标准字段规范

以下 11 个字段为全局统一标准，所有任务汇总表（快照与台账）均使用此字段集。

| 字段 | 类型 | 说明 | 备注 |
| :--- | :--- | :--- | :--- |
| **任务名称** | 必填 | 简洁描述这件事是什么 | 建议 10 字以内 |
| **所属项目/模块** | 必填 | 归属哪个项目代号或功能模块 | 如：iS-Hub / NexFlow / iS-Core |
| **优先级** | 必填 | P0 紧急 / P1 高 / P2 中 / P3 低 | P0 = 当前对话必须处理 |
| **任务类型** | 必填 | 决策 / 执行 / 待确认 / 信息同步 | 见下方类型说明 |
| **当前状态** | 必填 | 见状态标签体系 | 见下方状态说明 |
| **阻塞原因** | 条件填 | 仅当状态为 🔴 已阻塞 时填写 | 简述阻塞根因 |
| **下一步动作（人）** | 必填 | 需要人工做什么 | 无需人工介入时填「—」 |
| **下一步动作（AI）** | 必填 | 需要哪个 Agent 做什么 | 无需 AI 介入时填「—」 |
| **负责方** | 必填 | 人工 / Agent 代号（如 iS-Core / iS-Hub） | 可多方并列 |
| **依赖项** | 选填 | 推进前需要等待的前置条件 | 无依赖时填「—」 |
| **最后更新** | 必填 | 日期，格式 YYYY-MM-DD | — |

## 三、任务类型说明

| 类型 | 含义 | 典型场景 |
| :--- | :--- | :--- |
| **决策** | 需要人工拍板才能推进 | 方案选择、优先级裁决、资源分配 |
| **执行** | AI 或人工正在推进的具体工作 | 代码开发、文件撰写、数据处理 |
| **待确认** | 已有产出，等待人工审阅或确认 | 草稿审核、方案确认、字段核对 |
| **信息同步** | 需要在工作空间之间或人与 AI 之间对齐信息 | 状态通报、跨项目协调、背景补充 |

---

## 四、状态标签体系

| 标签 | 含义 | 触发条件 |
| :--- | :--- | :--- |
| 🔵 **待启动** | 已识别，尚未开始 | 任务刚被记录，无任何推进动作 |
| 🟡 **进行中** | 正在推进，无阻塞 | 有明确执行动作在进行 |
| 🔴 **已阻塞** | 有明确阻塞原因，无法推进 | 必须同时填写「阻塞原因」字段 |
| ⏸️ **待决策** | 需要人工裁决才能继续 | 任务类型为「决策」且尚未得到结论 |
| ✅ **已完成** | 结果已交付或已归档 | 产出物已确认，无后续动作 |

> **状态可随时增补**，新增状态需在本文件 v 版本中更新，并通知所有已接入工作空间。

## 五、双形态输出机制

### 5.1 快照（Snapshot）

**定位**：对话级消耗品，记录本次对话涉及的任务状态，对话结束时输出，不持久化。

**触发词**：`输出任务快照`

**输出规范**：
- 直接在对话中以 Markdown 表格输出
- 仅列本次对话中被提及或推进的任务
- 表格标题注明：`## 任务快照 · [日期] · [工作空间代号]`
- 不写入任何文件，不推送 GitHub

**示例触发场景**：对话即将结束时，用户说「输出任务快照」，AI 即输出本次对话的任务全貌。

---

### 5.2 台账（Ledger）

**定位**：项目级资产，跨对话持续累积，是项目的真实状态记录，需版本管理。

**触发词**：`更新任务台账`

**输出规范**：
- 写入对应项目目录下的 `TASK_LEDGER_[项目代号].md` 文件
- 推送至 GitHub 对应项目路径
- 表格标题注明：`## 任务台账 · [项目代号] · 最后更新 [日期]`
- 每次更新为全量覆盖（不追加），确保台账始终是最新全貌
- 更新后须在对话中告知用户：「台账已更新，路径：[文件路径]」

**台账文件命名规范**：`TASK_LEDGER_[项目代号].md`，如 `TASK_LEDGER_iS-Hub.md`

## 六、触发词完整清单

| 触发词 | 形态 | 动作说明 |
| :--- | :--- | :--- |
| `输出任务快照` | 快照 | 输出本次对话任务状态的 Markdown 表格，不写文件 |
| `更新任务台账` | 台账 | 更新并推送项目台账文件至 GitHub |
| `读取任务台账` | 台账 | 从 GitHub 读取当前项目的台账文件并展示 |
| `新增任务 [任务名]` | 两者 | 向当前快照或台账中追加一条新任务记录 |
| `标记完成 [任务名]` | 两者 | 将指定任务状态更新为 ✅ 已完成 |
| `全局任务审查` | 台账 | 读取所有活跃项目台账，输出跨项目阻塞项与 P0 任务汇总 |

## 七、工作空间接入指南

任何工作空间（Manus Project / GPT Project）需要激活本 Skill，只需在系统提示词中加入以下一段：

```
【任务情况汇总 Skill】
本工作空间已接入 Synexa iS 全局任务情况汇总 Skill。
Skill 定义文件：carefulxiao-cell/Synexa-iS-OIOS/00-master/TASK_SUMMARY_SKILL_v1.0.md
触发词：
- 输出任务快照：输出本次对话任务状态表格
- 更新任务台账：更新并推送项目台账文件
- 读取任务台账：读取当前项目台账
- 新增任务 [任务名]：追加新任务
- 标记完成 [任务名]：更新任务为已完成
- 全局任务审查：跨项目阻塞项与 P0 汇总
执行时严格遵循 Skill 文件中的字段规范与输出格式，不得自行增减字段。
```

## 八、版本演进规则

- 字段增补、状态标签新增、触发词调整，均须更新本文件版本号（v1.x）
- 字段删除或字段语义重大变更，须升级主版本号（v2.0）并通知所有已接入工作空间
- 每次版本更新后，CONTEXT_OS.md 待同步事项须同步记录

## 九、与现有机制的关系

| 现有机制 | 关系说明 |

| INSTRUCTION_TRACKER | 追踪「指令」（AI 收到的操作指令）；本 Skill 追踪「任务」（业务推进单元）；两者互补，不重叠 |
