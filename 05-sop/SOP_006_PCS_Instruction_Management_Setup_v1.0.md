# SOP_006: PCS 项目组指令管理机制建立指南 (v1.0)

**适用对象**：iS-Core (中央策略室)
**目标**：在任意 PCS (项目组) 空间内，快速建立标准化的「指令汇总表」与「指令生命周期管理机制」，确保多框协同（策略框与执行框）的高效与清晰。

---

## 1. 机制核心理念

在多框协同模式下，策略框（如本框）负责出指令，执行框负责写代码。为了避免指令遗漏、冲突或执行顺序混乱，必须在策略框建立一个**全局唯一的指令汇总表**，并遵循**标准化的指令生命周期**。

### 1.1 指令生命周期 (SOP_005)
`对齐 -> 生成 -> 审核 -> 入仓 -> 下发(按批次) -> 执行 -> 反查 -> 完成 -> 归档`

### 1.2 批量下发策略
- **串行**：修改同一文件（如 `schema.ts`）或存在逻辑依赖的指令。
- **并行**：操作不同文件、互不干扰的指令，可打包为同一批次下发。

---

## 2. Core 执行指令包（直接复制下发给 PCS 智能体）

当 Core 需要在一个新的或现有的 PCS 项目中建立此机制时，请直接将以下内容发送给该 PCS 智能体：

```markdown
> **【系统指令】建立 PCS 标准化指令管理机制**
> 
> 请在当前项目中建立与 NexFlow 相同的指令管理机制。请按以下步骤执行：
> 
> **第一步：创建指令追踪表**
> 在项目文档目录（如 `docs/`）下创建 `INSTRUCTION_TRACKER.md`，包含以下结构：
> 1. **执行批次策略**：说明当前待执行指令的批次划分及理由（串行/并行）。
> 2. **待执行指令（按批次顺序）**：列出待执行的指令包。
> 3. **已完成指令**：记录已完成的指令及对应的 commit hash。
> 4. **已废弃指令**：记录因冲突或共识变更而废弃的指令。
> 
> **第二步：规范汇总表字段**
> 在你我对话中输出的指令汇总表，必须严格包含以下字段：
> `编号 | 描述 | 优先级 | 批次 | 状态 | 核心设计共识 | 备注`
> 
> **第三步：遵循指令生命周期与废弃协议**
> 1. **生成**：每次生成指令包后，必须同步更新 `INSTRUCTION_TRACKER.md`。
> 2. **下发**：明确告知我（用户）当前应下发给执行框的批次及触发话术。
> 3. **废弃**：若新共识推翻旧指令，必须先从仓库删除旧指令文件，并在追踪表中标记为「🚫 已废弃」，然后再生成新指令，绝不保留歧义文档。
> 
> 请确认是否理解并立即初始化 `INSTRUCTION_TRACKER.md`。
```

---

## 3. 机制维护要求

1. **定期审查**：Core 应定期要求 PCS 智能体输出最新的指令汇总表，检查是否存在长期阻塞的批次。
2. **冲突处理**：当发现指令冲突时，Core 应强制 PCS 智能体执行「废弃协议」，清理旧文档。
