## 一、任务目标（TBF）

构建 Synexa iS 治理体系的可交互网站，以全局架构图 v1.2 为导航主界面，将 GitHub 仓库中的 `.md` 文件结构化呈现，支持节点交互、详情卡片查阅、AI 辅助新增录入与内容导出，并配备账号体系与草稿协作机制。

**一句话定义**：让 Synexa iS 体系的治理内容从静态文件变成可交互、可查阅、可录入的在线知识管理台。

---

## 二、MVP 交付标准（逐项验收）

### 2.1 主页 · 架构图导航
- 主画布白底，完整呈现架构图 v1.2 的四层结构（iS-Core + L4/L3/L2/L1）
- 架构图以 SVG 或 Canvas 渲染，**非截图**，节点可交互
- **鼠标悬停节点** → 浮出 Tooltip 气泡卡片，展示：
  - 框名称
  - 层级归属
  - 一句话定义
  - 当前状态（活跃 / 待建立 / 暂停）
- **点击节点** → 跳转至该节点的详情页

### 2.2 详情页 · 结构化卡片
每个节点详情页包含以下模块：

| 模块 | 内容 |
| :--- | :--- |
| 基本信息 | 框名称 / 代号 / 层级 / 框类型 / 当前状态 |
| 职能定义 | 一句话定义 + 职能边界（做什么 / 不做什么） |
| 关联文件 | 该节点对应的文件清单（可点击查看文件内容） |
| 关联机制 | 涉及的机制（ISYNC / TBF / SOP 系列等） |
| 触发词 | 在该框内生效的触发词列表 |
| 指令清单 | 当前有效指令摘要（可展开查看完整内容） |
| 推进状态 | 当前活跃任务 / 最近更新 / 阻塞项 |
| 操作区 | 新增条目 / 导出 / 提交草稿 |

### 2.3 账号体系
- 登录方式：账号密码（沿用 NexFlow 模式）
- 三级角色：
  - **超管**：全部权限（新增、编辑、审核合并、用户管理）
  - **项管**：可新增草稿、提交审核，不可直接合并
  - **成员**：只读 + 提交草稿

### 2.4 新增录入（AI 辅助对齐）
- 入口：详情页操作区「新增条目」按钮
- 流程：
  1. 用户输入非结构化文字（模糊描述、想法片段）
  2. AI 自动对齐为标准卡片字段（调用 LLM API）
  3. 用户确认或手动修改字段
  4. 提交草稿 → 管理员审核 → 并入 GitHub 仓库

### 2.5 协作模式（一阶段）
- 多人可读：所有角色均可查阅全部内容
- 草稿提交：项管/成员可提交草稿，不直接写入
- 管理员审核合并：超管审核通过后，内容写入 GitHub 并更新展示
- **实时块级协同编辑**：不在本期范围，放二阶段

### 2.6 数据导出
- 支持格式：Markdown / JSON
- 导出范围：单个卡片 / 整个板块 / 全量导出

### 2.7 左边栏导航
固定侧边栏，包含以下板块：

| 板块名称 | 数据来源 | 说明 |
| :--- | :--- | :--- |
| 机制汇总 | `CONTEXT_OS.md` 机制注册表 | 所有已注册机制列表 |
| 触发词汇总 | `TRIGGER_GLOSSARY.md` | 11 个全局触发词及响应逻辑 |
| 文件清单 | `EXECUTION_TRACKER.md` 编撰线 | 12 个治理文件 + 状态标签 |
| 指令清单 | `06-isync/` 目录 | 全局有效指令归档 |
| 对话组管理 | `WORKSPACE_REGISTRY.md` | 所有对话框的全局管理台（名称/框类型/项目/状态/ISYNC状态/指令升级项） |

## 三、技术选型建议

| 层 | 建议方案 | 说明 |
| :--- | :--- | :--- |
| 前端框架 | React + TypeScript + TailwindCSS | 与 NexFlow 保持一致 |
| 架构图渲染 | D2 SVG 导出 + 前端交互层叠加 | 保持与源文件一致 |
| 数据源 | GitHub API 读取 `.md` 文件 | 无需独立数据库，仓库即数据层 |
| AI 对齐 | OpenAI API（gpt-4.1-mini） | 模糊输入→标准卡片字段对齐 |
| 后端 | Node.js + FastAPI（轻量） | 处理 GitHub 写入、用户认证 |
| 数据库 | MySQL（用户账号体系） | 沿用 NexFlow 模式 |
