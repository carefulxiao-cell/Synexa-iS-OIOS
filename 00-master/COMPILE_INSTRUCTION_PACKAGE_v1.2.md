## 三、文件生产规范

1. **每个文件生产前**：先读取 `CONTEXT_OS.md` 确认最新全局状态，避免与已有裁决冲突
2. **文件命名**：遵循 `SOP_002` 命名规范，版本号格式 `_v[主版本].[次版本]`
3. **生产完成后**：将完整文件内容输出至对话，等待「中枢-智核中枢·iS-Core」确认入库后，由 iS-Core 推送 GitHub 并更新 `EXECUTION_TRACKER.md`
4. **重大内容变更**：触发 CONTEXT_OS.md 待同步事项更新，并提示 GPT 同步

## 四、回报与入库流程（严格遵循 SOP_008）

**编撰框严禁自行推送 GitHub。** 所有文件的入库动作由 iS-Core 执行。

标准流程如下：

```
Step 4：编撰框生产初稿
    ↓
Step 5：将完整文件内容输出给用户，带回「中枢-智核中枢·iS-Core」审核
         （不得只给摘要，必须输出完整文件内容）
    ↓
Step 6：「中枢-智核中枢·iS-Core」审核，提出修改意见 → 编撰框修订 → 直至终稿通过
    ↓
Step 7：iS-Core 收到「确认入库」后，由 iS-Core 推送 GitHub
         并更新 EXECUTION_TRACKER.md 对应任务状态
```

**每完成一个 P0/P1 任务，编撰框须：**
1. 将完整文件内容输出至对话，等待用户带回「中枢-智核中枢·iS-Core」审核后入库
2. 不得在未收到「确认入库」指令前推送任何文件至 GitHub
3. 若涉及 CONTEXT_OS.md 内容变更，在输出时注明，由 iS-Core 决定是否同步更新
4. **禁止自行宣布任务关闭或终稿确认。** 编撰框无权判断任务是否完成。任何「任务关闭」「终稿确认」的裁决，必须由「中枢-智核中枢·iS-Core」发出。编撰框遇到特殊情况（如发现已入库版本已包含所需修正），只能回报：「[情况说明]，请 iS-Core 确认是否以此为终稿，编撰框等待指令。」不得自行宣布。
