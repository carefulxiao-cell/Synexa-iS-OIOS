# 《Nex₂U PCS 实际结构模板 v0.2》

⸻

## 0. 文档说明

本模板用于作为 智食引擎·Nex₂U 的项目中枢系统（PCS）主模板，承载该项目的：
* 项目定义
* 当前状态
* 任务推进
* 决策记录
* 规则沉淀
* 文件索引
* 角色协同
* 验证与复盘

本模板是 Nex₂U 的单项目运行基线，不替代总纲与 Context OS，但必须与二者保持一致。

### 1.6 一句话定义
将非结构化的健康餐饮、营养逻辑与供应链经验，转化为可计算、可执行、可复用的结构化规则系统。

### 1.7 项目本质
Nex₂U 不是单一产品，不是单纯菜单工具，而是一个围绕健康餐系统的 规则引擎 + 结构化生成系统 + 项目验证样板。

### 1.8 不做什么
* 不做纯内容型健康资讯平台
* 不做只有展示层、没有规则底层的页面系统
* 不做仅靠人工经验驱动、无法复用的临时方案
* 不做脱离供应链与履约现实的空中设计

## 2. 项目目标区

### 2.1 总目标
建立一个可将健康餐逻辑、营养结构、原料映射、供应链约束与出品规则进行统一组织的项目级规则系统。

### 2.2 当前阶段目标
* 完成基础结构建模
* 完成核心链路拆解
* 建立首版规则引擎框架
* 跑通第一轮试运行闭环

### 2.3 本轮核心目标
* 明确页面 → 规则 → 任务 → 交付 的映射关系
* 形成首版项目章程与项目蓝图
* 建立可持续更新的状态板与决策日志
* 验证 SSADS 五层是否可在真实项目中落地

### 2.4 成功标准
* 关键链路可跑通
* 主要规则被结构化表达
* 项目状态可被持续维护
* 任务分工可被明确执行
* 首轮经验可沉淀为模板

## 11. AI 交接协议

### 11.1 进入本项目时必须先读
1. SSADS 总纲
2. Context OS 当前版本
3. Nex₂U PCS 当前版本
4. 最新决策日志
5. 当前任务板

### 11.2 输出要求
所有输出必须：
* 与当前项目定义一致
* 与现行决策一致
* 明确区分“已确认 / 待验证 / 假设项”
* 能回写到相应模块
* 不得以聊天内容替代正式更新

### 11.3 更新要求
以下变化必须更新 PCS：
* 项目目标变化
* 当前阶段变化
* 当前核心任务变化
* 关键阻塞项变化
* 形成关键决策
* 试运行结果形成
* 模板进入升级条件
