# Nex₂U｜番医饭堂经营数据专项字典与管理链路基线 v0.3

> **文件性质**：项目常态使用基线文件  
> **适用范围**：番医饭堂采购汇总、营收汇总、损益表、每日经营流水拆解表、产品结构表、产能测算表、飞书智能体引用说明  
> **版本说明**：v0.3 在 v0.2 的基础上，将日常短码统一为 **S编号·短字** 格式，例如 S1·订、S2·堂、S3·病；并继续保留系统辅助码作为第二优先级。  
> **当前状态**：工作基线 v0.3，可直接复制到飞书文档作为统一术语与表格字段说明。  
> **维护原则**：凡涉及采购、营收、损益、生产、履约、产能测算的表格，优先引用本文件术语，避免同一概念在不同表中多名、多义、多口径。

## 一、基线判断

番医饭堂的数据管理不能只按“采购表、营收表、损益表”三张财务结果表推进，而应先建立统一的**经营结构语言**。否则采购端只知道买了什么，营收端只知道卖了多少，损益端只看到总账结果，无法追溯到真实的产品结构、生产负荷、场景来源和履约成本。

本基线文件的核心作用，是把经营数据统一到一条可计算链路上：

> **原料 SKU → BOM → 结构点 SKU → 组合 SKU → 餐别/售卖 SKU → 场景线 → 履约单元 → 损益对象**。

这条链路的管理目标，是让采购、生产、销售、履约、财务和经营分析能够使用同一套结构语言，形成可复盘、可推演、可校准的经营数据底座。

## 二、编码原则

番医饭堂后续应同时保留两类编码，但使用优先级不同。

| 编码类型 | 使用优先级 | 用途 | 示例 |
|---|---:|---|---|
| **日常短码** | 第一优先级 | 用于飞书文档、采购表、营收表、损益表、团队沟通和日常引用。 | S1·订、S2·堂、S3·病。 |
| **场景线编号** | 第一优先级 | 用于统一场景线顺序和数据透视。 | S1、S2、S3。 |
| **系统辅助码** | 第二优先级 | 用于后续系统字段、接口、数据表英文编码或跨系统映射。 | EMP-ORD、PAT-DINE。 |

管理原则是：**对人沟通用 S编号 + 中点短码，对系统映射可加英文辅助码**。在飞书文档和经营表格中，应以用户已建立的 S1—S11 体系为主，不应以英文缩写替代日常短码。

## 四、场景线使用规则

### 4.1 飞书文档引用规则

飞书文档中第一次出现某条场景线时，建议使用完整写法：**编号 + 场景线名称 + 日常短码**。后续可只使用编号或短码。

| 第一次出现 | 后续简写 |
|---|---|
| S1 员工订餐 / 员工预订（S1·订） | S1 或 S1·订 |
| S4 病区预售（S4·预） | S4 或 S4·预 |
| S10 感控 / 特殊限制膳食（S10·感） | S10 或 S10·感 |

### 4.2 表格字段引用规则

采购、营收、损益、每日流水表中，建议至少保留三个场景线字段：

| 字段 | 示例 | 用途 |
|---|---|---|
| 场景线编号 | S1 | 用于排序、透视、归集。 |
| 场景线短码 | S1·订 | 用于人工识别和日常沟通。 |
| 场景线名称 | 员工订餐 / 员工预订 | 用于文档说明和正式报表。 |

如果后续进入系统化建模，可增加第四个字段：**系统辅助码**，例如 EMP-ORD、WARD-PRE、SPEC-NUT。

### 4.3 与原14类订单的关系

此前用于订单量说明的14类业务项，属于更细的**业务来源 / 订单类型**；S1—S11 是更高一层的**场景线归集口径**。两者不是互相替代，而是上下级关系。

| 原业务项 | 建议归入场景线 | 说明 |
|---|---|---|
| 员工订餐数 | S1 员工订餐 / 员工预订 | 若实际为提前订餐，则归 S1。 |
| 员工堂食数 | S2 员工堂食 | 现场堂食归 S2。 |
| 病患销售数 | S4 病区预售 或 S3 病患堂食 | 若为病区配送/预订，归 S4；若为现场堂食，归 S3。 |
| 病患堂食数 | S3 病患堂食 | 现场堂食归 S3。 |
| 健康中心 | S6 体检中心 / 健康管理 | 普通体检与健康管理归 S6。 |
| 月子餐 | S8 月子 / 产康 | 月子餐与产康营养支持归 S8。 |
| 手术室餐室 · 午餐 | S11 专项营养 / 专病营养 或新增专项子类 | 当前可先归 S11，后续如量大可独立子类。 |
| 手术室餐室 · 早餐 | S11 专项营养 / 专病营养 或 S9 术后康复 | 取决于实际对象与用途。 |
| 手术室餐室 · 宵夜 | S11 专项营养 / 专病营养 | 当前按专项营养/专项供餐归集。 |
| 介入手术室 · 午餐 | S11 专项营养 / 专病营养 | 当前按专项营养/专项供餐归集。 |
| 行政专家餐 | S7 VIP体检中心 或 S11 专项营养 / 专病营养 | 若强调高服务感，归 S7；若只是专项供餐，归 S11。 |
| 行政超时餐 | S11 专项营养 / 专病营养 或内部管理子类 | 当前可先归 S11，后续可设内部超时餐子类。 |
| 志愿者餐 | S11 专项营养 / 专病营养 或公益支持子类 | 当前可先归 S11，后续可设公益支持子类。 |
| 爱心餐 | S11 专项营养 / 专病营养 或公益支持子类 | 当前可先归 S11，后续可设公益支持子类。 |

> **待确认点**：手术室餐、介入手术室、行政专家餐、行政超时餐、志愿者餐、爱心餐，是否要继续作为 S11 下的子场景，还是在后续版本中扩展为 S12—S16。当前建议先不扩展主编号，避免场景线体系过早膨胀。

## 五、核心术语字典

| 序号 | 术语 | 标准定义 | 主要用途 | 边界说明 | 示例 |
|---:|---|---|---|---|---|
| 1 | **结构点 SKU** | 结构点 SKU 是设计基础单位，也是实际需要被生产、采购、备料、计时、核算的最小产品结构单元。 | 用于生产排程、产能测算、时间轴推演、产品成本核算、损益拆解。 | 结构点 SKU 不等同于售卖 SKU；它更接近“厨房实际要做什么”。 | 白粥、包子、炒粉、米饭、主荤A、小炒B、时蔬C、例汤、小菜、水果、牛奶、炖汤。 |
| 2 | **场景线** | 场景线是不同对象、不同路线、不同需求矩阵的来源集合。 | 用于区分需求来源、交付路径、价格机制、服务要求和履约约束。 | 场景线不等同于产品，也不等同于餐别；它回答“卖给谁、送到哪、按什么要求履约”。 | S1员工订餐、S2员工堂食、S3病患堂食、S4病区预售、S8月子产康、S11专项营养。 |
| 3 | **早餐 SKU / 午餐 SKU / 晚餐 SKU / 加餐 SKU** | 餐别 SKU 是面向消费和结算的产品组合单位，代表不同餐别下的需求矩阵组合。 | 用于销售统计、营收归集、客单价分析、套餐定价、餐别损益核算。 | 餐别 SKU 是前台结算口径，结构点 SKU 是后台生产口径。 | 早餐单品、早餐套餐、正餐单品、加菜单品、午餐套餐、晚餐套餐、宵夜套餐、加餐组合、手术室午餐、行政专家餐。 |
| 4 | **售卖 SKU** | 售卖 SKU 是用户实际购买、系统实际结算、营收表实际记录的销售单位。 | 用于收入确认、销量统计、客单价计算、销售结构分析。 | 一个售卖 SKU 可以由多个结构点 SKU 组合而成，也可能只是一个单品。 | ￥12病患午餐、￥10员工堂食、￥15手术室午餐、￥110月子餐一日组合。 |
| 5 | **组合 SKU** | 组合 SKU 是由多个结构点 SKU 按规则组合形成的餐食方案。 | 用于连接后台生产与前台销售，是产品设计和结算之间的桥。 | 组合 SKU 可以固定，也可以半固定；自由选择餐属于弱组合，专项餐属于强组合。 | 主荤1+小炒2+时蔬1+例汤1+小菜1，即手术室午餐组合 SKU。 |
| 6 | **需求矩阵** | 需求矩阵是由对象、餐别、价格、产品结构、交付路径、时间要求共同形成的需求模型。 | 用于判断每条场景线需要什么产品、什么时间交付、以什么价格结算。 | 需求矩阵不是单一订单，而是一类需求的稳定规则。 | S4病区预售午餐矩阵、S2员工堂食午餐矩阵、S8月子产康全日矩阵。 |
| 7 | **生产负荷单位** | 生产负荷单位是把不同产品换算成对厨房资源的占用强度。 | 用于避免把“一个包子”和“一份完整套餐”都粗暴算成一份。 | 它不是销售单位，而是产能测算单位。 | 包子主要占蒸柜负荷，粥主要占粥线和窗口负荷，专项餐主要占分装、标签、配送复核负荷。 |
| 8 | **等效套餐量** | 等效套餐量是把单品、套餐、专项餐、自助人次统一折算成可比较的生产压力。 | 用于判断当天真实生产强度，而不是只看订单数。 | 等效套餐量只用于内部测算，不建议直接作为对外经营口径。 | 10个包子可能只等于若干份标准套餐的综合生产压力；1份行政专家餐可能高于1份普通套餐。 |
| 9 | **工艺线** | 工艺线是厨房实际生产能力的分类通道。 | 用于把结构点 SKU 分配到热厨、蒸柜、粥粉面、炖汤、凉菜、分装、标签、配送等生产环节。 | 工艺线不按销售名称划分，而按制作方式、设备占用和人力动作划分。 | 热厨线、蒸制线、粥粉面线、炖汤线、主食线、分装线、贴标复核线、配送线。 |
| 10 | **成本归集单元** | 成本归集单元是采购、人工、能耗、包材、损耗最终归入的核算对象。 | 用于打通采购汇总表、单品成本表、餐别毛利表、场景线损益表。 | 成本归集单元可以是结构点 SKU，也可以是组合 SKU，但建议先落到结构点 SKU。 | 主荤A的食材成本、包子的面点成本、手术室午餐组合的综合成本。 |
| 11 | **采购归集类** | 采购归集类是把原材料按成本和用途进行分类的采购管理口径。 | 用于采购汇总、供应商管理、价格波动分析、损耗追踪。 | 采购归集类不是菜品名称，而是原材料大类。 | 肉禽类、水产类、蔬菜类、米面粮油类、调味品类、乳品类、水果类、包材类。 |
| 12 | **原料 SKU** | 原料 SKU 是采购端实际采购和入库的最小物料单位。 | 用于采购、库存、成本、供应商、价格波动管理。 | 原料 SKU 不等同于结构点 SKU；多个原料 SKU 组成一个结构点 SKU。 | 鸡腿肉、猪肉片、青菜、米、面粉、鸡蛋、牛奶、餐盒。 |
| 13 | **BOM 配方关系** | BOM 是原料 SKU 到结构点 SKU 的用量关系。 | 用于计算单品成本、采购需求、损耗、毛利和备货量。 | 没有 BOM，就只能做粗略采购汇总，不能做真正损益拆解。 | 一份主荤A = 鸡肉150g + 调味料若干 + 油耗 + 包材分摊。 |
| 14 | **履约单元** | 履约单元是最终需要被交付、点收、复核的单位。 | 用于配送、标签、装箱、病区/科室交接和异常追踪。 | 履约单元不一定等于售卖 SKU；一笔订单可能拆成多个履约单元。 | 病区A午餐50份、手术室午餐180份、月子餐第2餐5份。 |
| 15 | **路线批次** | 路线批次是按交付路径和时间窗口组织的一组履约单元。 | 用于控制装车、配送、交接、保温和120分钟履约。 | 路线批次是交付管理口径，不是生产口径。 | 午餐病区第一批、午餐手术室定点批、员工订餐配送批。 |
| 16 | **损益对象** | 损益对象是最终需要判断赚钱、亏钱、效率高低的经营分析对象。 | 用于把收入、食材成本、人工、包材、能耗、损耗、配送成本归集到具体经营单元。 | 损益对象可以按场景线、餐别 SKU、组合 SKU 或结构点 SKU 分层查看。 | S4病区预售线损益、S2员工堂食线损益、S8月子产康线损益、早餐 SKU 损益。 |
| 17 | **结算单位** | 结算单位是用户支付、系统计价和营收记录所采用的单位。 | 用于统一营收口径、客单价口径和销售数量口径。 | 结算单位不一定等于生产单位，也不一定等于履约单位。 | 个、碗、份、人次、套、日组合。 |
| 18 | **核算口径** | 核算口径是某张表在统计时采用的对象、单位、时间和归集规则。 | 用于避免采购、营收、损益表之间数字看似一致但含义不同。 | 每张经营表都应注明核算口径。 | 按自然日、按餐别、按场景线、按售卖 SKU、按结构点 SKU。 |
| 19 | **时间颗粒度** | 时间颗粒度是经营数据被记录、汇总和分析的最小时间单位。 | 用于支持产能压力、峰值窗口和履约效率分析。 | 营收可按日汇总，但生产履约建议至少支持15分钟颗粒度。 | 15分钟窗口、餐别窗口、自然日、周、月。 |
| 20 | **数据责任源** | 数据责任源是某一字段或表格的原始产生部门或系统。 | 用于判断数据可信度、修正路径和责任归属。 | 同一指标只能有一个主责任源，其他来源作为校验源。 | 采购来自采购/仓库，营收来自POS/收银，生产来自厨房，配送来自运营。 |

## 六、专项字典结构管理

专项字典不应只做一张术语表，而应分成可维护的九类字典。每类字典对应一类数据对象，分别服务采购、生产、销售、履约和损益分析。

| 字典模块 | 解决的问题 | 关键字段 | 建议责任人 | 更新频率 |
|---|---|---|---|---|
| **术语字典** | 统一结构点 SKU、场景线、餐别 SKU 等概念。 | 术语、定义、用途、边界、示例、版本。 | 项目负责人 / 经营分析。 | 有新增概念时更新。 |
| **场景线字典** | 统一 S1—S11 及其对象、价格、路径。 | 场景线编号、名称、短码、对象、餐别、价格、交付路径、服务要求。 | 运营 / 财务。 | 场景变化时更新。 |
| **结构点 SKU 字典** | 统一厨房实际生产单品。 | 结构点编码、名称、单位、工艺线、是否高频、是否专项。 | 厨房 / 运营。 | 菜品或生产结构变化时更新。 |
| **售卖 SKU 字典** | 统一前台结算产品。 | 售卖编码、名称、餐别、价格、结算单位、适用场景线。 | 收银 / POS / 财务。 | 售价或销售组合变化时更新。 |
| **原料 SKU 字典** | 统一采购和库存物料。 | 原料编码、名称、规格、单位、供应商、采购归集类。 | 采购 / 仓库。 | 每次新增物料或供应商时更新。 |
| **BOM 配方字典** | 打通原料到结构点成本。 | 结构点 SKU、原料 SKU、标准用量、损耗率、成本。 | 厨房 / 采购 / 财务。 | 配方或价格变化时更新。 |
| **工艺线字典** | 打通结构点到生产能力。 | 工艺线、设备、人力、标准时间、批量能力、瓶颈说明。 | 厨房 / 运营。 | 设备、人力、流程变化时更新。 |
| **履约路线字典** | 打通订单到配送交付。 | 路线编码、对象、交付点、批次、截单时间、责任人。 | 配送 / 运营。 | 路线或交付要求变化时更新。 |
| **损益口径字典** | 打通收入、成本、费用、毛利。 | 损益对象、收入口径、成本口径、费用分摊规则、毛利口径。 | 财务 / 经营分析。 | 月度或口径调整时更新。 |

## 七、核心关系模型

经营数据应按“层级递进”管理，而不是按表格孤立管理。每一层都应清楚回答一个问题，并为下一层提供结构化输入。

| 层级 | 关键词 | 回答的问题 | 与下一层关系 |
|---|---|---|---|
| 采购层 | 原料 SKU | 买什么、多少钱、从哪里来。 | 原料通过 BOM 转为结构点成本。 |
| 配方层 | BOM | 原料如何变成可生产单品。 | BOM 决定结构点 SKU 的标准成本。 |
| 生产层 | 结构点 SKU | 厨房实际生产什么。 | 结构点按规则组成组合 SKU。 |
| 组合层 | 组合 SKU | 结构点如何组合成餐食方案。 | 组合 SKU 被包装为售卖 SKU 或餐别 SKU。 |
| 销售层 | 餐别 SKU / 售卖 SKU | 用户买什么、如何结算。 | 售卖 SKU 落入不同场景线。 |
| 场景层 | 场景线 | 谁买、在哪吃、怎么交付。 | 场景线产生不同履约单元。 |
| 履约层 | 履约单元 / 路线批次 | 送到哪里、何时完成、谁交接。 | 履约结果反向影响成本、损耗和服务质量。 |
| 经营层 | 损益对象 | 哪条线赚钱、亏钱、低效或高效。 | 损益结果反向修正采购、产品、价格和排程。 |

## 八、链路原则

### 8.1 一条主链路

所有采购、营收、损益、生产、履约相关资料，默认沿以下主链路组织：

> **原料 SKU → BOM → 结构点 SKU → 组合 SKU → 餐别/售卖 SKU → 场景线 → 履约单元 → 损益对象**。

这条链路是番医饭堂经营数据的主索引。任何新表格如果不能说明自己处于链路中的哪一层，就容易形成孤立数据。

### 8.2 两套基本口径

| 口径 | 面向对象 | 解决问题 | 典型表格 |
|---|---|---|---|
| **前台经营口径** | 用户、收银、财务收入。 | 卖了什么、卖了多少、收了多少钱。 | 营收表、售卖 SKU 表、餐别销售表。 |
| **后台生产口径** | 厨房、采购、仓库、运营。 | 实际做了什么、消耗什么、占用什么产能。 | 结构点 SKU 表、BOM 表、产能压力表、采购汇总表。 |

前台经营口径不能替代后台生产口径。一个“￥12套餐”在营收表里是一个售卖 SKU，但在生产端可能拆成主荤、小炒、时蔬、米饭、汤、包材和配送复核等多个结构点与动作。

### 8.3 三类管理对象

| 对象 | 定义 | 管理重点 |
|---|---|---|
| **物的对象** | 原料 SKU、结构点 SKU、组合 SKU、售卖 SKU。 | 编码、单位、成本、价格、配方、库存。 |
| **人的对象** | 员工、病患、门诊、体检、VIP、月子、术后、特殊膳食、专项营养等对象。 | 需求、价格、服务标准、结算方式。 |
| **路的对象** | 场景线、履约单元、路线批次。 | 截单、分装、装车、配送、交接、异常反馈。 |

三类对象必须分开建模。不能用“产品名称”同时代表物、对象和路线，否则后续采购、营收、损益都会混乱。

### 8.4 四个不得混用

| 不得混用项 | 正确区分 |
|---|---|
| **结构点 SKU ≠ 售卖 SKU** | 前者是生产基础单位，后者是结算销售单位。 |
| **场景线 ≠ 餐别 SKU** | 前者是对象与路线，后者是消费结算产品。 |
| **订单数 ≠ 完整套餐数** | 订单中可能包含包子、粥、单品、自助人次或专项餐。 |
| **采购金额 ≠ 单品成本** | 采购金额需要通过 BOM、损耗、库存和用量分摊，才能进入单品成本。 |

## 九、管理落表建议

### 9.1 采购汇总表

采购汇总表不应只记录供应商和金额，还应能反向支持结构点成本。建议至少保留以下字段：

| 字段 | 用途 |
|---|---|
| 日期 | 用于月度、周度、日度采购分析。 |
| 供应商 | 用于价格、质量、稳定性分析。 |
| 原料 SKU | 用于连接库存和 BOM。 |
| 采购归集类 | 用于大类成本分析。 |
| 规格 / 单位 | 用于避免斤、公斤、箱、袋混用。 |
| 数量 | 用于消耗和库存核对。 |
| 单价 / 金额 | 用于价格波动和成本分析。 |
| 可关联结构点 SKU | 用于判断该原料主要服务哪些产品。 |
| 可关联场景线 | 用于判断该原料主要服务哪些业务需求。 |
| 损耗或不可用量 | 用于还原真实成本。 |
| 责任源 | 用于确认数据来自采购、仓库还是财务。 |

### 9.2 营收汇总表

营收汇总表应在销售金额之外，保留售卖 SKU、餐别 SKU 和场景线字段。否则后续无法判断哪一类业务贡献收入，哪一类业务占用资源但收益不足。

| 字段 | 用途 |
|---|---|
| 日期 / 餐别 | 用于按时间和餐次统计。 |
| 场景线编号 | 用于按 S1—S11 统一归集。 |
| 场景线短码 | 用于人工识别和飞书文档引用。 |
| 售卖 SKU | 用于还原用户实际购买项目。 |
| 餐别 SKU | 用于早餐、午餐、晚餐、加餐维度分析。 |
| 结算单位 | 用于区分个、碗、份、人次、套。 |
| 数量 | 用于销量与负荷换算。 |
| 单价 / 金额 | 用于收入确认和客单价分析。 |
| 交付路径 | 用于判断是否产生分装、配送和交接成本。 |

### 9.3 损益表

损益表应支持多层查看，不能只看总收入、总成本和总毛利。建议至少支持四个损益对象：场景线、餐别 SKU、售卖 SKU、结构点 SKU。

| 损益对象 | 适合回答的问题 |
|---|---|
| 场景线损益 | S1—S11 哪条业务线赚钱、亏钱、占用资源高。 |
| 餐别 SKU 损益 | 早餐、午餐、晚餐、加餐哪个效率更好。 |
| 售卖 SKU 损益 | 哪个销售产品毛利高、复购高、复杂度高。 |
| 结构点 SKU 损益 | 哪个实际生产单品成本高、损耗高、工艺压力大。 |

## 十、后续维护规则

### 10.1 新增术语规则

新增术语必须同时说明五项内容：**定义、用途、边界、示例、责任源**。只给名称不给边界的术语，暂不进入基线。

### 10.2 新增场景线规则

新增场景线必须先判断是否可以归入 S1—S11 的某条既有主线。只有当新场景在对象、产品结构、履约路径、结算方式或损益逻辑上都明显不同，才考虑新增 S12 及以后编号。

### 10.3 表格引用规则

凡采购、营收、损益、产能、履约相关表格，建议在说明区加入以下字段：

| 字段 | 说明 |
|---|---|
| 引用字典版本 | 例如：经营数据专项字典 v0.3。 |
| 核算口径 | 说明按日、按餐别、按场景线、按售卖 SKU 或结构点 SKU。 |
| 数据责任源 | 说明数据来自采购、仓库、POS、厨房、配送或财务。 |
| 更新时间 | 说明数据更新时间。 |
| 未解决口径 | 标注仍需确认的字段或假设。 |

### 10.4 数据治理原则

经营数据的治理原则是**先统一语言，再统一表格，最后统一系统**。在术语未统一之前，不建议直接推进复杂自动化；否则系统会把混乱口径自动放大。

## 十二、一句话原则

番医饭堂后续所有经营数据整理，都不应只问“这张表怎么做”，而应先问：

> **这张表处在原料、配方、生产、组合、销售、场景、履约、损益这条链路的哪一层？它向上承接什么，向下输出什么？它归入 S1—S11 哪条场景线？**

只有这样，采购汇总表、营收表和损益表才能从静态记录升级为可计算、可追踪、可复盘的经营系统资产。
