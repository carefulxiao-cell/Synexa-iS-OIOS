## 一、退回原因

编撰框交付的 WORKSPACE_REGISTRY v2.0 初稿经 iS-Core 审核，表结构不符合要求，需按本指令重新生产。

主要问题：
1. 层级编号缺失，组与框打平在同一层，无法体现父子关系
2. 「代号」字段冗余（代号已包含在名称中），需删除
3. 「框类型」字段值混乱（部分用「框」，部分用其他描述），需统一
4. 部分 L2 引擎组内部对话框信息缺失或不完整

## 二、新表结构规范

### 2.1 字段定义

| 字段名 | 说明 | 示例值 |
|---|---|---|
| **编号** | 层级编号，父子关系用小数点表示 | L1 / L1.1 / L1.1.1 |
| **名称** | 组或框的完整名称，与 Manus 对话组实际名称一致 | 智核中枢·iS-Core |
| **类型** | 固定值：`组` / `中枢框` / `执行框` / `编撰框` / `审查框` / `功能框` / `讨论框` | 组 |
| **定位** | 一句话说清职责，不超过30字 | 董事会主控入口，全局裁决、项目孵化、体系治理 |
| **触发词/进入模式** | 有则填写，无则留空 | `读取基线`、`汇总指令` |

### 2.2 层级编号规则

```
L1         → 全局枢纽（层级标题行，不是具体组）
L1.1       → L1 下的第1个组
L1.1.1     → L1.1 组内的第1个框
L1.1.2     → L1.1 组内的第2个框
L1.2       → L1 下的第2个组
L2         → 核心业务引擎（层级标题行）
L2.1       → L2 下的第1个引擎组
L2.1.1     → L2.1 组内的第1个框
...以此类推
```
