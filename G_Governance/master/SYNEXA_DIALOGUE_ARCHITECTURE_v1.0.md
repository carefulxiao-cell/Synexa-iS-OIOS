# Synexa iS 全局生态四层对话机制架构 v1.0

## 1. 核心概念回应与定义

### 1.1 "不加载全局上下文，直接响应"的理解
**定义**：指在**同一个对话框内**，Agent 仅基于该对话框的常驻指令（Project Instructions）和历史聊天记录进行回答，**不主动去 GitHub 读取** `CONTEXT_OS.md` 等外部全局状态文件。
**目的**：降低日常轻量沟通的 Token 损耗。
**边界**：当用户明确要求"读取基线"或涉及跨项目裁决时，才触发外部读取。

### 1.2 "每个对话启动前由中枢设计第一段话"的可行性
**判断：完全可行且高度科学。**
**机制**：这被称为**「中枢引导启动机制（Hub-Guided Initialization）」**。
任何新的执行框或功能框在开启前，必须先在对应的【中枢框】内生成一段标准化的「启动 Prompt」。这段 Prompt 包含了该对话框的定位、目标、边界和初始上下文。用户只需将这段 Prompt 复制到新对话框的第一句话，即可高质量启动，避免了"冷启动"的质量参差不齐。

## 2. 四层对话机制架构设计

为了实现"生产-发展-完善-循环"的闭环，我们将整个 Synexa iS 生态的对话机制划分为四个层级，从微观到宏观层层嵌套：

### Layer 1: 同框对话机制（Intra-Dialog Mechanism）
**定位**：管理单一对话框内的沟通质量与状态留存。
**核心机制**：
1. **中枢引导启动**：首语必须由中枢框生成并输入，确立基调。
2. **APE 原则（先对齐→再生产→再执行）**：任何实质性动作前，必须先确认逻辑。
3. **反逻辑自洽检验**：输出结论时，必须提供对立假设或外部验证路径。
4. **ISYNC 指令汇总**：通过 `汇总指令` 触发词，将本框内的高价值指令提炼并推送至中央仓。

### Layer 2: 同组协同机制（Intra-Project Mechanism）
**定位**：管理同一个项目组（如 iS-NexFlow）内不同对话框（中枢框、执行框、审查框）之间的配合。
**核心机制**：
1. **指令流转闭环**：中枢框生产指令 → 执行框接收并编码 → 审查框比对代码与指令。
2. **TBF 任务基线对齐**：所有框共享同一份 TBF（任务目标基线）文件，作为唯一对齐标准。
3. **FBR 功能基线审查**：通过 `全面审查 [系统]` 触发词，审查框自动核对执行框的产出是否符合中枢框的定义。

### Layer 3: 跨组通联机制（Inter-Project Mechanism）
**定位**：管理不同项目组（如 NexFlow 与 Nex2U）之间的资源共享与状态同步。
**核心机制**：
1. **全局状态账本（CONTEXT_OS）**：所有项目组的重大状态变更，必须回写至中央仓的 CONTEXT_OS。
2. **跨组依赖声明**：当 A 项目需要 B 项目的接口时，必须在 A 的 TBF 中声明依赖，并在 B 的中枢框中生成对应任务。
3. **基线读取触发**：通过 `读取基线` 触发词，任何项目组都可以获取全局最新状态，避免信息孤岛。

### Layer 4: 全局生态演进机制（Eco-Evolution Mechanism）
**定位**：管理整个 Synexa iS 体系的自我进化与规则更新。
**核心机制**：
1. **核心原则统管（CORE_PRINCIPLES）**：所有对话框受统一的最高原则约束。
2. **体系注册表（SYSTEM_REGISTRY）**：集中管理所有对话组、RACI、版本和待解决问题（Open Issues）。
3. **定期回归与重构**：由 iS-Core 定期触发全局审查，清理冗余对话框，升级常驻指令模板。

## 3. 触发词清单（Trigger Words List）

为了支撑上述机制，全生态通用以下标准触发词：

| 触发词 | 适用层级 | 触发动作 | 适用场景 |
| :--- | :--- | :--- | :--- |
| `读取基线` | Layer 3 | 读取 GitHub 中央仓的 CONTEXT_OS 和 _INDEX | 需要了解全局状态或跨项目情况时 |
| `汇总指令` | Layer 1 | 提炼本框内指令并推送至 `06-isync/` | 阶段性讨论结束，需要留存指令资产时 |
| `全面审查 [系统]` | Layer 2 | 读取 FBL/ISYNC，比对代码与指令完成度 | 版本交付前或定期质量检查时 |
| `验证 [结论]` | Layer 1 | 强制 Agent 提供对立假设或外部验证方案 | 做出重大决策前，防止逻辑自洽 |
| `生成启动语` | Layer 2 | 根据当前上下文，生成用于开启新对话框的 Prompt | 准备开启新的执行框或功能框时 |

## 4. 体系维度升级版（7+1 维度）

在原有的 7 个维度基础上，增加「生态机制」维度，形成完整的 8 维治理体系：

1. **角色与责任汇总（RACI）**：谁负责什么。
2. **核心原则汇总（CORE_PRINCIPLES）**：遵循什么。
3. **项目对话组及框汇总（WORKSPACE_REGISTRY）**：在哪里做。
4. **决策日志汇总（Decision Log）**：做过什么裁决。
5. **指令汇总（ISYNC）**：生产了什么指令。
6. **版本与交付物汇总（VERSION_REGISTRY）**：做出了什么。
7. **待解决问题汇总（Open Issues）**：还有什么问题。
8. **生态机制汇总（ECO_MECHANISMS）**：系统如何运转（即本文件的四层机制）。
