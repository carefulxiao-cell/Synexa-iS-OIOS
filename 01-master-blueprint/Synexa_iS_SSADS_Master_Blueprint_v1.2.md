# 《Synexa iS · SSADS 总纲 v1.2》

## 0. 文档性质声明

本文件为 Synexa iS（智核中枢）的最高结构性文件，用于定义：
* 体系结构
* 方法路径
* 工具原则
* 治理规则

本文件具备以下属性：
* 唯一结构基线
* 上位规则来源
* 所有项目与系统的解释依据

⸻

## 1. 体系定义（锁死表达）

### 1.1 体系名称

* 对外品牌名：Synexa iS（智核中枢）/ OIOS（组织级智能操作系统）
* 技术结构名：SSADS（集团智能协同体系）

### 1.2 体系结构

* SSADS｜五层协同架构
* 8步建构路径（含 Step 0）
* 4组工具集合

### 1.3 一句话定义（锁定版）

Synexa iS（智核中枢），是一套组织级智能操作系统（OIOS）。它以治理与认知中枢为总控，以 SOP 为方法规则，以 Skills 为能力资产，以 Agent Matrix 为协同编排，以 Digital Employee 为持续执行，并通过项目中枢系统（PCS）完成项目实例化落地的组织级智能操作架构。

⸻

## 3. 五层协同架构（不可改动层）

五层结构为体系底盘，不得随项目任意调整：
1. 治理与认知中枢
2. SOP（规则层）
3. Skills（能力层）
4. Agent Matrix + Digital Employee（执行层）
5. PCS（项目落地层）

⸻

## 4. 8步建构路径（唯一项目生成路径）

所有项目必须按以下路径建构：
0. **双重门禁**
   * **0A 战略对齐（SAP）**：确认项目是否成立、目标是否清晰、风险是否可控
   * **0B 启动检查**：确认层级归位、复用评估
1. **定义对象**
2. **锚定价值**
3. **建模业务**
4. **映射协同**
5. **建设中枢**
6. **试运行**
7. **固化复制**

⸻

工具只服从三件事：
* 路径
* 结构
* 输出

不得反向定义业务或结构。

## 7. PCS（项目中枢系统）制度要求

每个重点项目必须具备：

**固定标配（不可缺失）**
* 项目章程
* 项目蓝图
* 当前任务板
* 决策日志
* 文件索引
* 术语表
* AI交接协议

**AI交接协议最小字段（必须包含）**
* 当前版本号
* 断点描述（停在哪里）
* 下一步任务（接手做什么）
* 禁止事项（绝对不能碰什么）

**最小状态字段（必须维护）**
* 当前阶段
* 当前版本
* 当前负责人
* 当前目标
* 当前核心任务
* 当前阻塞项
* 下一里程碑
* 最近更新时间

状态字段必须同步项目实际，不得滞后。

**执行协议（EP）归属说明**
执行协议（Execution Protocol, EP）不构成独立体系层级，而作为 PCS 的标准子模块存在，用于规范项目内部具体步骤的输入、动作、输出、校验与回写。

**执行协议（EP）版本与生效规则**
* 每个 Step 在同一时间只能存在一个“当前生效版本”的执行协议
* EP 的更新必须标注版本号，并在 PCS 文件索引中同步更新
* 所有执行必须基于当前生效版本，不得引用历史版本
* 若执行结果与 EP 冲突，应优先修订 EP，而不是绕过 EP
