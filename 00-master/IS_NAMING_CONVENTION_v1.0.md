## 一、命名原则总纲

Synexa iS 体系的命名服务于两个目标：**对内精准传递概念本质**，**对外建立可持续的品牌认知资产**。命名不是标签，而是概念的第一层定义。一个好的命名应当在被说出的瞬间，就传递出它所指向的本质。

命名遵循三条总原则：

**① 精准优先**：名称必须准确反映概念的核心本质，不允许为了好听而牺牲准确性。

**② 持久优先**：避免使用当下流行词汇或技术术语，选择经典词根（拉丁语/古希腊语/经典英文），确保命名在技术迭代后仍然有效。

**③ 体系一致**：同一体系内的命名应当形成内在关联，构成可叙事的整体，而非孤立的词汇堆砌。

## 二、语言风格选择标准

### 何时使用拉丁语 / 古希腊语词根

满足以下条件中两条及以上时，优先使用拉丁/古希腊语词根：

| 条件 | 说明 |
|------|------|
| **核心认知构件** | 该概念是体系的基础结构，需要长期稳定存在，不随技术迭代而改变 |
| **跨语言传播需求** | 该概念有国际化传播需求（融资、合作、品牌建设） |
| **隐喻深度** | 拉丁/希腊词根能精确表达概念的本质隐喻，而非仅描述功能 |
| **内部受众为主** | 该概念主要面向团队、智能体、高智受众，不需要被普通用户直接理解 |

### 何时使用大众通用语言（中文直白 / 英文通俗）

满足以下条件之一时，使用大众通用语言：

| 条件 | 说明 |
|------|------|
| **操作层工具** | 使用者需要快速理解功能，降低认知成本优先 |
| **高频对外介绍** | 该概念需要频繁向客户、合作伙伴解释，沟通效率优先 |
| **探索期概念** | 该概念尚未定型，不值得投入命名资产 |

### 双层命名结构

当一个概念同时面向内部和外部受众时，采用双层命名：

```
内部代号（拉丁/希腊词根）+ 中文副名（直白表达功能）
示例：iS-Cortex（协同皮层）
```

对外介绍时使用中文副名，对内调用时使用代号，两者指向同一概念。

## 三、命名结构规范

### iS 模块命名格式

```
iS-[词根]（中文副名）
```

- **词根**：拉丁/希腊/经典英文，1-2个音节，发音清晰，无歧义
- **中文副名**：2-4字，直接表达功能或核心隐喻
- **连字符**：iS 与词根之间使用连字符（-），不使用空格或下划线

### 文件命名格式

```
IS_[功能描述]_v[版本号].md
```

- 全大写前缀 IS，下划线分隔，版本号格式为 v1.0
- 示例：`IS_SOP_FILE_GOVERNANCE_v1.1.md`、`IS_NAMING_CONVENTION_v1.0.md`

## 五、命名禁止事项

- **禁止使用纯缩写**作为正式名称（如 CIS、DSL），缩写只作为辅助标记
- **禁止使用当下流行技术词汇**作为核心命名（如 GPT-xxx、AI-xxx），避免命名随技术迭代失效
- **禁止同一体系内出现语义冲突的命名**，新命名前需检查与现有命名的关系
- **禁止未经确认的命名进入正式文件**，探索期命名在文件中需标注「待确认」

## 六、命名评审流程

1. **提议**：提出候选命名，附词根来源、本义、隐喻说明
2. **对齐**：与 iS-Core 确认命名是否符合体系一致性原则
3. **确认**：双方确认后，录入本文件「已确认命名清单」
4. **写入**：更新相关基线文件，同步推送 GitHub
