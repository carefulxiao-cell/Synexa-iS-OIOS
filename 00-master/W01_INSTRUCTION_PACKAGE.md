构建 Synexa iS 治理体系的可交互网站，以全局架构图 v1.2 为导航主界面，将 GitHub 仓库中的 `.md` 文件结构化呈现，支持节点交互、详情卡片查阅、AI 辅助新增录入与内容导出，并配备账号体系与草稿协作机制。

## 二、MVP 交付标准

### 2.1 主页 · 架构图导航

**【强制约束，最高优先级】**

- 主画布**必须直接使用 `00-master/SYNEXA_GLOBAL_ARCHITECTURE_v1.2.png` 原图作为底图**
- **禁止自行重绘或重新生成架构图**，当前自行重绘的版本废弃
- 在原图上叠加透明交互热区（每个节点对应一个可点击/悬停区域）
- 热区坐标必须基于原图中各节点的**实际像素位置精确标注**，不能估算，建议用图像坐标拾取工具逐节点确认后写入
- 视觉效果必须与原 PNG 完全一致，白底，不做任何样式改动
- **鼠标悬停节点** → 浮出 Tooltip 气泡卡片，展示：框名称 / 层级归属 / 一句话定义 / 当前状态
- **点击节点** → 跳转至该节点的详情页

### 2.2 详情页 · 结构化卡片

每个节点详情页包含以下模块：

| 模块 | 内容 |
| :--- | :--- |
| 基本信息 | 框名称 / 代号 / 层级 / 框类型 / 当前状态 |
| 职能定义 | 一句话定义 + 职能边界（做什么 / 不做什么） |
| 关联文件 | 该节点对应的文件清单（可点击查看文件内容） |
| 关联机制 | 涉及的机制（ISYNC / TBF / SOP 系列等） |
| 触发词 | 在该框内生效的触发词列表 |
| 指令清单 | 当前有效指令摘要（可展开查看完整内容） |
| 推进状态 | 当前活跃任务 / 最近更新 / 阻塞项 |
| 操作区 | 新增条目 / 导出 / 提交草稿 |

### 2.3 账号体系

- 登录方式：账号密码（沿用 NexFlow 模式）
- 三级角色：
  - **超管**：全部权限（新增、编辑、审核合并、用户管理、排序调整）
  - **项管**：可新增草稿、提交审核，不可直接合并
  - **成员**：只读 + 提交草稿

### 2.4 新增录入（AI 辅助对齐）

- 入口：详情页操作区「新增条目」按钮
- 流程：
  1. 用户输入非结构化文字（模糊描述、想法片段）
  2. AI 自动对齐为标准卡片字段（调用 LLM API，使用 `gpt-4.1-mini`）
  3. 用户确认或手动修改字段
  4. 提交草稿 → 管理员审核 → 并入 GitHub 仓库

### 2.5 协作模式（一阶段）

- 多人可读：所有角色均可查阅全部内容
- 草稿提交：项管/成员可提交草稿，不直接写入
- 管理员审核合并：超管审核通过后，内容写入 GitHub 并更新展示
- **实时块级协同编辑**：不在本期范围，放二阶段

### 2.6 数据导出

- 支持格式：Markdown / JSON
- 导出范围：单个卡片 / 整个板块 / 全量导出

**机制汇总 / 触发词汇总 / 指令清单 统一规范：**

- 布局：**单列向下滚动**（不使用两列网格）

- 卡片右侧：状态 badge（已启用 / 待建立 / 已升级）
- 卡片底部：「点击查看详情」

## 五、对话组管理板块结构

**三层结构：**

```
顶层（全局级别分类）
  ├─ 集团级基线与枢纽系统（G-LEVEL）
  ├─ 核心业务系统（BUSINESS SYSTEMS）
  ├─ 垂直场景与应用项目（VERTICAL PROJECTS）
  └─ 实验性项目（EXPERIMENTAL）
      ↓ 展开
一级：项目组（如 iS-Core / NexFlow / Nex2U / Nexsply）
      ↓ 展开
二级：框类型分组（中枢框 → 执行框 → 编撰框 → 审查框 → 讨论框）
      ↓ 点击卡片
对话框详情管理页（定位描述 / 职能边界 / 关联文件 / 机制 / 触发词 / 指令清单 / 推进状态 / 操作区）
```

**排序规则：**
- 顶层分类顺序固定（G-LEVEL → BUSINESS → VERTICAL → EXPERIMENTAL）
- 项目组内框类型顺序固定（中枢框置顶，其余按执行→编撰→审查→讨论）
- 超管可手动调整同层级内排列顺序

**数据来源**：`WORKSPACE_REGISTRY.md`（F-06，编撰线待生产，生产完成后自动读取渲染，无需手动录入）
