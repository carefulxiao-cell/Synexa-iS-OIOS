## 四、系统任务精准定义

### 4.1 Nex₂U 的系统级任务（System Mission）

Nex₂U 的系统任务是：**将围绕"优质健康生活方式"的非结构化知识、经验与供应链现实，转化为可计算、可驱动多端应用的结构化智能协同系统。**

具体而言，这包含三项不可分割的子任务：

**任务 T1：知识结构化**
将健康饮食的营养学逻辑、饮食原则、人群适配规则等非结构化知识，转化为机器可读的规则库与知识图谱。

**任务 T2：生成引擎化**
基于结构化规则，建立可根据输入条件（人群特征、场景需求、供应链约束）自动生成符合要求的餐食方案的计算引擎。

**任务 T3：多端协同化**
将引擎能力以标准化接口输出至 NuBō（B端运营）、Nufō³（C端体验）、NuStā（内容知识），实现一套底层驱动多端应用的协同架构。

### 4.2 三项任务的优先级与时序

```
T1（知识结构化）→ T2（生成引擎化）→ T3（多端协同化）
```

这是强依赖的串行关系：没有 T1，T2 无规则可算；没有 T2，T3 无内容可输出。当前 Step 3 的核心工作，是完成 T1 的基础结构建模，并为 T2 建立框架。

## 六、边界定义（做什么 / 不做什么）

### 6.1 Nex₂U 做什么

- 建立健康饮食的规则引擎底层（知识结构化 + 规则计算）
- 驱动 B 端（NuBō）的供给管理与运营协同
- 驱动 C 端（Nufō³）的个性化饮食体验生成
- 驱动内容端（NuStā）的健康知识体系组织
- 与 Nexsply 建立标准化的供应链数据接口

### 6.2 Nex₂U 不做什么

- 不直接面向终端用户提供 C 端产品（那是 Nufō³ 的职责）
- 不承担供应链采购与执行（那是 Nexsply 的职责）
- 不做纯内容型健康资讯（那是 NuStā 的职责）
- 不在规则引擎未建立前直接开发 UI 或产品界面
- 不用人工经验替代结构化规则

### 6.3 Nex₂U 与 Nexsply 的关系边界

| 维度 | Nex₂U | Nexsply |
| :--- | :--- | :--- |
| **定位** | 智能协同引擎（规则 + 生成） | 优质供应链服务（采购 + 履约） |
| **关系** | 规则需求方 / 接口调用方 | 供给能力方 / 数据提供方 |
| **接口方向** | Nex₂U 向 Nexsply 输出"原料需求规格" | Nexsply 向 Nex₂U 反馈"可用原料清单 + 约束" |
| **协同机制** | 通过标准化数据接口，而非人工沟通 | 同上 |
