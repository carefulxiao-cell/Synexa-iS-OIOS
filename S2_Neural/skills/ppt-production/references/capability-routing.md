# 能力协同与工具适配

## 激活机制

先识别当前瓶颈，再选择最小充分能力组合：判断条件 → 核实当前设备可用skill与工具 → 读取方法及工具定义 → 传入任务上下文 → 接收可供PPT使用的结果 → 核验并交接。

显式触发`@PPT生产`不会自动启用外部连接、取得权限或一次性调用所有能力。关联skill不一定有独立可调用函数：通常由主执行者读取其规范并应用；需要工具操作时再调用该能力的实际工具。

## 工具选择与交接

1. 以用户格式、编辑需求及可用环境决定路线，不先选生成模型。
2. 用户指定PowerPoint、Keynote、Google Slides或其他应用时，区分“可导出供其打开”与“能实际操作该应用”。未经连接核实不得宣称后者。
3. 当前Manus演示稿制作遵循官方Slides规范。主要可编辑交付采用可用的原生PPTX路线；图片模式仅在用户或官方模板确实要求时使用。
4. 外部应用或连接需求先检查当前会话配置，优先可满足任务的已授权连接；新权限或保护流程按要求停下，不借此扩展范围。
5. 使用工具前读取完整契约。保存项目ID、路径与实际返回状态；失败时先核实副作用，避免重复初始化或覆盖。
6. 生成或搜集的素材先检查，再放入页面；资料充足时不进行无关外部研究。
7. 对其他环境的文件和工具先发现、切换并核实，不能凭历史路径调用。

## 最小执行记录

内部只需记录：本轮问题、采用能力、实际动作、结果进入哪页、关键核验。不能仅因skill文件已创建就声称已经使用。关联能力提供支持，其成果始终服务于PPT任务，不扩展成独立网站、报告或其他生产任务。
