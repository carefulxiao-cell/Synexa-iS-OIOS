# SOP_001_FBR_Mechanism_v1.1

> **版本**：v1.1
> **生效日期**：2026-04-16
> **维护主体**：iS-Matrix（智核矩阵）
> **定位**：定义超智体系所有系统级项目的标配机制——功能基线与审查机制（FBR 机制）。
> **核心逻辑**：FBR 机制的核心是一个**「指令积累 → 代码比对 → 验证闭环」**的三步工作流。它确保所有开发共识都沉淀为中央仓的指令汇总文件，并以此为基准，通过正反向扫描系统代码包，及时发现偏差并完善增补。

---

## 1. 机制概述

**FBR (Functional Baseline & Review) 机制** 是为每个系统建立一个动态功能基线（Functional Baseline），并配合正反向审查测试机制，以确保系统功能的长期可维护性和稳定性。它是 TBF（任务目标基线文件）机制在功能维度的自然延伸和深化。

### 1.1 核心载体：功能列表文件 (FBL)

- **定义**：FBL (Functional Baseline List) 是记录系统所有核心功能模块预期状态与实际审查结果的动态文件。它是**所有开发指令共识的汇总池**。
- **存放位置**：作为每个系统 PCS（项目控制系统）的核心附件，存放在对应项目的 `docs/` 目录下。
- **命名规范**：`[Project_Code]_FBL_v[X.X].md` (例如：`NexFlow_FBL_v3.0.md`)
- **模板参考**：`05-sop/FBL_Template_v1.1.md`

## 2. 运行机制：三步闭环 (Three-Step Loop)

FBR 机制的运行严格遵循以下三步闭环逻辑：

### 步骤一：指令共识积累 (Accumulation)
- **动作**：所有开发沟通、开发指令共识，必须形成文件（如 TBF、指令包）。
- **沉淀**：这些文件必须留存积累在中央仓对应的位置（如 `docs/` 目录），并将其核心功能点汇总提取至 FBL 文件中，形成**指令基准**。

### 步骤二：激活审查与代码比对 (Review & Compare)
- **触发**：在需要时（如版本交付、定期回归），通过标准触发词激活审查机制。
- **动作**：智能体根据 FBL（指令汇总文件），一一扫描系统代码包（中央仓数据包），进行严格比对。
- **核查点**：指令中要求的功能，代码包中是否真实存在且逻辑一致？代码包中存在的功能，是否在指令汇总中有记录？

### 步骤三：正反向验证与完善 (Validation & Refinement)
- **正向验证**：指令要求的功能 → 代码是否实现？（防遗漏、防幻觉）
- **反向验证**：代码已有的功能 → 指令是否记录？（防野蛮生长、防回归错误）
- **闭环动作**：发现偏差情况，及时生成修复任务，完善、增补或去重代码与指令，确保两者始终镜像对齐。

## 3. 标准触发词与执行序列 (SOP)

### 3.1 标准触发词

为了在各工作空间中快速激活审查机制，统一使用以下标准触发词：

**`全面审查 [系统代号]`**

例如：`全面审查 NexFlow`、`全面审查 Nex2U`、`全面审查 Nexsply`

### 3.2 触发后的标准执行序列

当 Agent 收到 `全面审查 [系统代号]` 时，必须按以下顺序执行：

| 步骤 | 动作 | 产出 |
| :--- | :--- | :--- |
| 1 | 读取该系统最新 FBL 文件（指令汇总基准） | 获取功能基线 |
| 2 | 扫描系统代码包（中央仓数据包），提取实际功能逻辑 | 代码功能快照 |
| 3 | **执行正反向比对**：<br>a. 正向：FBL 指令项 -> 代码包是否实现？<br>b. 反向：代码包功能 -> FBL 是否有记录？ | 比对差异清单 |
| 4 | 输出「系统状态确认」：健康功能数 / 缺失项（指令有代码无） / 冗余项（代码有指令无） | 可视化状态报告 |
| 5 | 针对差异项，生成完善/增补/去重任务，并标注优先级 | 修复任务清单 |
| 6 | 将审查结论回写至 FBL 对应条目的「最后审查记录」字段 | FBL 更新 |

### 3.3 扩展变体（可选标准化）

如需区分审查深度，可进一步约定：

| 指示词 | 含义 |
| :--- | :--- |
| `审查 [系统代号]` | 默认：核心链路快速比对 |
| `全面审查 [系统代号]` | 所有功能条目逐项扫描比对 |
| `审查 [系统代号] [模块名称]` | 指定模块扫描比对（例如：`审查 NexFlow 文件中心`） |

---

*注：本 SOP 适用于超智体系下所有系统级项目，各项目组在初始化时必须基于 FBL 模板建立首版功能基线。*
