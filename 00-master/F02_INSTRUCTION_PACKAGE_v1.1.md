## 二、任务目标（TBF）

生产一份 **Synexa iS 体系 RACI 角色责任表**，明确体系内所有角色在七类核心动作上的权责边界，使任何人在任何协作节点都能快速查到「这件事谁负责、谁执行、谁需要知道」，消除权责模糊导致的重复决策和越界操作。

## 三、内容结构要求

### 3.1 角色清单（行）

RACI 矩阵的「行」为以下角色，必须全部覆盖，不得遗漏或新增未定义角色：

| 角色代号 | 角色名称 | 说明 |
|---|---|---|
| **User** | 用户层 | 体系最终决策者与人工中介，包括：主理人（肖健辉）及各业务/项目组授权成员（超级项管成员、项管协作人员等）。负责跨框传递指令、最终裁决与授权。 |
| **iS-Core** | 智核中枢 | L1 中枢框，基线治理、项目孵化、跨域裁决、GitHub 入库执行。**全局唯一的 GitHub 推送执行方。** |
| **iS-SCO** | 枢机经纬 | L1 策略框，战略推演与需求定义 |
| **iS-Matrix** | 智核矩阵 | L1 生产框，SOP / 规程 / 模板 / 数字员工指令生产 |
| **iS-Hub** | 智权枢纽 | L1 情报框，工具与 Agent 资源汇聚 |
| **iS-Lab** | 智核实验 | L1 实验框，灵感前测，不得超过最小验证阶段 |
| **编撰框** | 编撰岗（各组标配） | 各业务/项目/系统组的文件生产执行岗，生产后交对应中枢审核，不得自行入库 |
| **执行框** | 执行岗（各组标配） | 各业务/项目/系统组的系统/代码生产执行岗，里程碑截图回报对应中枢，不得自行入库 |
| **审查框** | 审查岗（各组标配） | 各业务/项目/系统组的质量核验执行岗，核验结果交对应中枢裁决，不得自行入库 |
| **L2 引擎框** | 各业务引擎对话组 | iS-Nex2U / iS-NexChef / iS-NexFlow / iS-NexMPC / iS-NexFA / iS-Nexsply / iS-Synexa，各引擎专属工作空间，在引擎范围内独立推进，向 iS-Core 汇报阻塞与里程碑 |
| **L3 项目框** | 各垂直项目对话组 | 具体项目推进，向 iS-Core 或对应 L2 引擎框汇报阻塞与里程碑 |

### 3.2 动作类型（列）

RACI 矩阵的「列」为以下七类核心动作，必须全部覆盖：

| 动作代号 | 动作名称 | 说明 |
|---|---|---|
| **D** | 决策（Decision） | 对方向、优先级、架构做出最终裁决 |
| **P** | 生产（Production） | 实际生产文件、代码、方案等产物 |
| **R** | 审核（Review） | 对产物进行质量核查，提出修改意见 |
| **A** | 入库（Archiving） | 将终稿推送至 GitHub 并更新追踪表（**全局统一由 iS-Core 执行**） |
| **N** | 通报（Notification） | 接收状态更新，无需参与执行 |
| **T** | 传递（Transfer） | 在框与框之间传递指令或产物（人工中介动作，由 User 执行） |
| **B** | 搭建（Building） | 引擎/平台/系统/网站的技术搭建与部署（执行框专属动作） |

### 3.3 RACI 值定义

| 值 | 含义 |
|---|---|
| **R** | Responsible（执行者）：实际完成该动作的角色 |
| **A** | Accountable（负责人）：对结果负最终责任的角色，每列只能有一个 A |
| **C** | Consulted（咨询方）：执行前需征询意见的角色 |
| **I** | Informed（知会方）：执行后需通知的角色 |
| **—** | 不参与 |

### 3.4 必须包含的场景矩阵（四个）

除全局角色×动作矩阵外，还需包含以下四个**场景级 RACI 小表**，说明具体流程中的权责：

1. **文件生产流程**（对应 SOP_008 七步工作流：对齐 → 指令 → 传递 → 生产 → 审核 → 修订 → 入库）
2. **项目立项流程**（Step 0A 最小定义 → PCS 创建 → 对话组建立 → 通报）
3. **GitHub 入库流程**（生产 → 完整输出 → 审核 → 确认 → 推送 → 状态更新）
4. **引擎/平台/系统/网站搭建流程**（需求定义 → 指令下发 → 执行框搭建 → 里程碑截图回报 → 审核 → 确认上线 → 入库记录）

## 五、边界与禁忌

1. **不得新增未在 WORKSPACE_REGISTRY v2.0 中定义的角色**，如遇角色不清晰，在输出时注明并等待 iS-Core 确认，不自行假设。
2. **每个动作列只能有一个 A（负责人）**，不得出现多个 A 共享的情况。
3. **L3/L4 对话组不单独列行**，统一归入「L3 项目框」或「L4 探索框」角色，避免矩阵过于庞大。
4. **不得在 RACI 表中定义新的流程或规则**，只反映已有 SOP 和基线文件中确认的权责关系。
5. **GitHub 推送统一归 iS-Core 执行**，这是全局通用原则，RACI 表中入库（A）列的 A 必须是 iS-Core，其他任何角色不得标注为 A 或 R。
6. **不得自行推送 GitHub**，生产完成后将完整文件内容输出至对话，等待 iS-Core 审核确认后入库。
