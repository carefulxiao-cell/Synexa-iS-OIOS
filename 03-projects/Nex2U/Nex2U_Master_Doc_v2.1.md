## 1. 项目定位与目标

### 1.1 一句话定义
Nex₂U 是一个**“结构驱动的健康稳态餐食生成引擎”**。它不仅局限于传统健康餐饮，而是对标全球领先的智能工具系统，将非结构化的营养逻辑、供应链经验与未来具身智能（Embodied AI）工具相连接，转化为可计算、可执行、可复用的结构化规则系统，提供广域包容且精准锁定的健康稳态支持餐食方案。

### 1.2 核心目标（三层）
*   **业务目标**：打造新一代优质饭堂及衍生增值服务体系，解决餐食履约中“营养要求高、原料变动大、供应链难匹配”的问题，实现降本增效与体验升级。
*   **系统目标**：建立一个连接自动化设备与具身智能的全局规则系统，统一组织健康餐逻辑、营养结构、原料映射、供应链约束与出品规则。
*   **本阶段目标**：**极速开发（3~4周内完成基础版）**，跑通从“用户需求”到“供应链匹配”的核心业务链条，完成首个 MVP（新一代优质饭堂）的落地，后续持续迭代完善。

## 2. 系统架构与边界（三层架构）

Nex₂U 整体遵循三层架构，明确各端边界：

### 2.1 Layer 1｜系统中枢层（System Nexus Layer）
*   **核心模块**：**Nex₂U（智食引擎）**
*   **职责**：统一决策逻辑生成、系统协同、数据流动与规则演进。
*   **包含**：P1 高质效全维科学菜单引擎、用户画像与场景状态识别、口味聚合与爆品系统、标签系统与推荐逻辑、规则迭代机制。

### 2.2 Layer 2｜执行层（Execution Layer）
*   **核心模块**：**NuBō（优食运维 - B端供给管理）**
*   **职责**：将系统中枢生成的逻辑，转化为真实供给与生产行为。
*   **包含**：团餐公司协同、厨房执行体系、菜单标准生产、运营协同流程。

### 2.3 Layer 3｜交互与呈现层（Interaction Layer）
*   **核心模块**：**Nufō³（食全食美 - C端饮食体验）**
*   **职责**：C 端用户的个性化饮食决策与体验平台，以及 B 端运营的高效工作台。
*   **包含**：
    *   手机端：点餐界面、推荐展示、轻量状态输入、个人饮食洞察面板。
    *   电脑端：运营及后台工作人员工作台（支持内外网部署，提升管理便利性）。
    *   平板端：现场服务与护士站协同。

### 2.4 第三支柱｜NuStā（健康稳态知识体系）
*   **定位**：Nex₂U 的知识引擎与信任锚。
*   **职责**：提供营养逻辑、食物结构原则、标签命名依据，以及信任解释（为什么推荐）。

## 3. 核心业务逻辑与结构化要素（六大核心数据库）

系统采用“三层-五维一引擎”结构体系，通过结构约束引擎实现可计算、可组合、可替换的餐食生成机制。

### 3.1 28个主题场景系统（Layer 1 入口层）
用于面向用户的餐食分类与选择，覆盖核心人群与主要膳食需求场景。
*   **早餐（4类）**：启动代谢（均衡早餐、轻负担早餐、体力早餐、高蛋白早餐）
*   **正餐（21类）**：
    *   **工作补能（4）**：医护补能、体力能量、日常均衡、轻负担晚餐
    *   **特殊膳食（9）**：术后恢复、肠胃调理、产妇营养、儿童营养、老年营养、肿瘤营养、流质饮食、半流质饮食、软食饮食
    *   **慢病管理（5）**：糖尿病餐/控糖友好、高血压餐、痛风饮食/关节友好、透析餐/肾友安心餐、血脂管理
    *   **功能食养（3）**：高蛋白强化、高纤饮食、抗炎修复
*   **加餐（3类）**：补能调节（能量加餐、蛋白加餐、轻食加餐）

### 3.2 餐型母型系统（Layer 2a 结构层）
将前端多变的需求收敛为标准化的生产模板，连接“营养逻辑”和“厨房生产”。
*   **12个正餐母型**：标准均衡餐、双蛋白营养餐、体力能量餐、高蛋白功能餐、高纤维代谢餐、抗炎轻负担餐、术后恢复餐、肠胃调理餐、老年温和餐、糖尿病控制餐、低嘌呤餐、软食流质餐。
*   **7个轻餐母型**：对应早餐与加餐的结构模板。

### 3.3 膳食营养结构点体系（Layer 2b 核心引擎）
对餐型母型的营养精度约束层，将母型拆解为具备明确营养功能、结构约束规则的标准化营养单元。
*   **编码体系**：P·C·V·E·PR
*   **六维分类（90个营养点框架）**：
    1.  **蛋白结构点 (Protein)**：解决修复、维持、功能支持。
    2.  **碳水结构点 (Carb)**：解决供能稳定性与血糖控制。
    3.  **脂肪结构点 (Fat/Energy)**：解决炎症、代谢、能量密度。
    4.  **蔬菜纤维结构点 (Veg/Fiber)**：解决肠道、饱腹、微量营养。
    5.  **控制约束结构点 (Constraint)**：解决医疗/慢病/限制。
    6.  **质构结构点 (Texture)**：解决吞咽与咀嚼问题。

### 3.4 工艺规则库（E01-E15）
定义烹饪工艺与食材的加工处理标准，确保餐食的质构、安全和特定营养目标的达成。

### 3.5 食材原料库（Layer 3 模块层）
系统的物料基础，为上层模块提供填充单元。约200+食材，每个食材带营养标签，可算法组合。

### 3.6 菜单/产品库（Layer 4 生产层）
系统的最终价值输出，连接抽象规则与具体产品，生成具体的菜单和SOP指导生产。

## 4. MVP 定义与开发规划（极速版：3~4周基本完成）

### 4.1 MVP 场景与目标
*   **首发场景**：新一代优质饭堂（以此为核心，衍生增值服务与产品内容）。
*   **目标**：3~4周内完成基本功能开发，跑通一个可复制、可扩张、可复盘的高质效最小闭环。

### 4.2 技术路线与工具链（H5 响应式网页战略）
*   **前端架构**：全面转向 H5 响应式跨端架构（Vite + React + TailwindCSS），自动适配手机端、电脑端（运营及后台工作人员工作台，支持内外网）和平板端。
*   **支付模式**：双轨支付（手机端 JSAPI 微信支付 + 电脑端 Native 扫码支付）。
*   **消息触达**：微信服务号绑定 OpenID，通过模板消息推送订单状态。
*   **硬件与运营**：飞鹅云打印 API（线下出单）、草料二维码（静态码）、飞书多维表格（菜品数据协同）。

### 4.3 极速落地搭建四阶段（3-4周）
1.  **阶段一：基础框架与身份支付（第1周）**：搭建前后端脚手架，攻克微信网页授权与双端支付联调。
2.  **阶段二：饭堂核心场景与后台管理（第2周）**：跑通点餐核心流程、菜单展示与运营管理后台基础功能。
3.  **阶段三：履约链路与硬件联调（第3周）**：对接厨房云打印机与服务号模板消息测试，打通数据闭环。
4.  **阶段四：试运行与交付（第4周）**：内部封闭测试，修复核心 Bug，完成基础版交付并准备上线。

## 5. 跨平台协同工作机制

为了在 3-4 周内极速推进开发，建立基于 GPT、Manus、Code 平台的协同机制：

### 5.1 角色分工
*   **GPT（数字系统架构师 D3）**：负责业务逻辑推演、营养结构设计、场景规则制定、文档结构设计。主导“想”和“设计”。
*   **Manus（执行型/协同型数字员工 D1/D2）**：负责执行层动作，包括代码开发、文件生成、GitHub 推送、系统架构图绘制（D2语言）。主导“做”和“落地”。
*   **GitHub（SSOT）**：所有输出文档、架构图、代码统一回写至 GitHub，两侧共享，保持全局状态一致。

### 5.2 结构化工作流（文字描述 -> 流程图 -> 编码打包）
1.  **需求输入**：用户在 GPT 侧输入业务逻辑。
2.  **结构化翻译**：GPT 将其翻译为标准结构化文档，更新 Master Doc。
3.  **同步与制图**：Manus 读取更新后的 Master Doc，同步生成/更新全局架构图（D2）。
4.  **任务拆解**：Manus 基于 MVP 规划，拆解前后端开发任务清单。
5.  **编码落地**：进入实际开发阶段，Manus 辅助代码生成与部署。
