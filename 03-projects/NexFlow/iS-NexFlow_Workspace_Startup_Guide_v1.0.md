# iS-NexFlow 工作空间启动指引

> **版本**：V1.0
> **日期**：2026-04-16
> **来源**：iS-Core 智核中枢
> **定位**：指导【超级项管·NexFlow】工作空间（Manus / GPT）的建立、基线配置与首阶段运转。

---

## 一、启动的本质判断

NexFlow 当前的真实状态是：**产品先行，治理滞后**。V2.6-brand 已在实战验证中，功能在跑，但缺少一个正式的 PCS 工作空间（专属对话组 + 系统提示词）和一套清晰的「策略室出指令 → 执行框写代码 → GitHub 同步」协作协议。

因此，启动的第一件事不是「继续开发功能」，而是**先把治理结构建起来，再在治理结构内推进功能迭代**。

---

## 二、Step 1｜建立专属工作空间（操作层）

这是最先要做的物理动作，不需要任何内容准备，只需要操作平台。

### 2.1 在 Manus 平台建立
新建一个 Project，命名为「**超级项管·NexFlow**」，在 Project Instructions 中粘贴以下系统提示词（直接可用）：

```markdown
你是 Synexa iS 体系在 Manus 平台的项目协同智能体，代号 iS-NexFlow，职能定位为【项目组 · PCS 执行空间】。

【身份定义】
你负责 NexFlow（超级项目管理）的全生命周期推进，包括功能规划、迭代指令生成、用户需求分析和产品演进管理。

【前置接入协议（每次对话强制执行）】
在执行任何任务前，必须按以下顺序完成：
1. 读取 carefulxiao-cell/Synexa-iS-OIOS 仓库中的 02-context-os/CONTEXT_OS.md（全局状态总账本）
2. 读取 carefulxiao-cell/nexflow 仓库中的 docs/iS-NexFlow_PCS_Briefing_v0.6.md（了解定位）
3. 读取 carefulxiao-cell/nexflow 仓库中的 todo.md（了解当前功能状态）
4. 输出「当前状态确认」：NexFlow 当前版本 / 进行中任务 / 阻塞项 / 下一个里程碑

【职能边界】
- 负责：功能规划、迭代指令生成、模块设计、用户需求分析、产品演进管理
- 不负责：体系基线裁决（归 iS-Core）、战略推演（归 iS-SCO）、跨项目优先级排序（归 iS-Core）
- 执行指令发送至 NexFlow-V2 执行框，代码通过 GitHub carefulxiao-cell/nexflow 与策略室同步

【协作约定】
- 策略室（iS-SCO）负责审核、监控、校正、设计，出指令
- NexFlow-V2 执行框负责写代码、跑测试、保存检查点
- GitHub 仓库 carefulxiao-cell/nexflow 作为两框之间的代码桥梁
- 文件未明确「转交出去」前均为草稿对齐阶段，每次更新输出完整最新版

【GitHub 仓库】
- 体系基线：carefulxiao-cell/Synexa-iS-OIOS
- 产品代码：carefulxiao-cell/nexflow
```

### 2.2 在 GPT 平台建立
同步建立对应的 GPT Project，命名一致（**超级项管·NexFlow**），Project Instructions 使用同等内容，并上传 `iS-NexFlow_PCS_Briefing_v0.6.md` 与本启动指引作为知识文件。

## 三、Step 2｜完成 PCS 正式文件（治理层）

工作空间建立后，第一项任务是由 iS-NexFlow 工作空间将现有的《PCS Briefing V0.6》转化为正式的 PCS 文件，包含以下七个基线组件：

| 组件 | 说明 | 当前状态 |
|------|------|---------|
| 项目章程 | 一句话定义、核心目标、价值主张 | PCS Briefing V0.6 已有，需格式化 |
| 项目蓝图 | 八大模块完整定义、版本路线图 | PCS Briefing V0.6 已有，需格式化 |
| 当前任务板 | V2.6 → V2.7 → V3.0 迭代任务清单 | 需从 nexflow/todo.md 同步 |
| 决策日志 | 历史关键决策记录 | 需从 iS-SCO 策略室存档整理 |
| 文件索引 | 所有相关文件的路径与版本 | 需新建 |
| 术语表 | 核心概念定义（如「信息不出系统」） | 需新建 |
| AI 交接协议 | 当前断点、禁止事项、下一步 | 需新建 |

**这一步在 iS-NexFlow 工作空间内完成，不在 iS-Core 处理。**

---

## 四、Step 3｜建立迭代推进节奏（执行层）

PCS 建立后，工作空间进入常规运转模式。NexFlow 当前处于 V2.6-brand 稳定基线，下一步迭代路径按以下节奏推进：

| 阶段 | 版本目标 | 核心任务 | 优先级 |
|------|---------|---------|--------|
| 当前 | V2.6-brand | 番禺中心医院食堂项目持续验证，收集真实问题 | 🔴 最高 |
| 近期 | V3.0 | 实施已完成的指令包：人力管理（/hr）+ 日常运营（/daily-ops）+ 文件中心（/files）重构 | 🟠 高 |
| 中期 | V3.1 | 健康看板（证件到期 / 巡检未跟进 / 培训未完成的统一预警视图） | 🟡 中 |
| 远期 | V3.x | 跨引擎协同接口（Nexsply / NexChef / Nex2U）+ 一键交付包 | ⚪ 规划中 |

**每次迭代的标准流程**：
```text
iS-SCO 策略室出指令
    ↓
iS-NexFlow 工作空间审核、拆解为开发任务
    ↓
NexFlow-V2 执行框写代码、跑测试
    ↓
代码推送至 carefulxiao-cell/nexflow
    ↓
iS-NexFlow 工作空间验收、更新 PCS 任务板
    ↓
关键决策回写 CONTEXT_OS（由 iS-Core 执行）
```
