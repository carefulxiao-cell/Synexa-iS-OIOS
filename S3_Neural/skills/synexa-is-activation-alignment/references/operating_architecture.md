# Synexa iS Operating Architecture v2.0 Draft

## Position

This architecture describes the internal operating structure of Synexa iS. It is part of the broader Synexa company architecture, not the entire company map.

## Three-layer operating model

### 1. Task Room Runtime Layer

A complex task is handled through a Task Room. The current conversation can become the Task Room. The Task Room organizes roles, capabilities, skills, execution packages, validation, and feedback.

### 2. Capability Domain Layer

The six historical workspaces become capability domains:

- Core: governance decision domain.
- SCO: strategic reasoning domain.
- Matrix: structured production domain.
- Hub: external intelligence domain.
- Lab: concept pretest domain.
- PCS: project execution domain.

These are not mandatory separate chat rooms. They can be invoked as views inside the current Task Room.

### 3. Asset Governance Layer

Outputs are governed through:

- GitHub
- CONTEXT_OS
- Skill Library
- SOP Library
- PCS project libraries
- Case Log
- Patch Log
- File Registry

## Larger Synexa context

Synexa company architecture may include:

- Brand Layer
- Business Scenario Layer
- Synexa iS Layer
- Execution Network Layer
- Value Creation Layer

The SIA architecture sits primarily inside the Synexa iS Layer and connects to execution and asset-governance layers.
