# 创生引擎·提取技能 (IS_GENESIS_EXTRACT_SKILL)

## 1. 技能定义
本技能是 IS_GENESIS 创生引擎在 **BUILD(建构)** 阶段的核心能力。用于将已完成或部分完成的代码工程、系统状态、业务逻辑等非结构化信息，提取并封装为标准化的 `DELIVERY_PACKAGE`（交付包），以便在 **VERIFY(验证)** 阶段进行审查。

## 2. 触发条件
- **触发词**：`提取系统交付包`
- **前置条件**：项目已进入 BUILD 阶段，且有可读取的代码库或文档。

## 3. 提取目标（五大原则）
1. **提取完整，不遗漏**：必须覆盖五类信息（代码本体、数据结构、运行状态、开发历史、业务逻辑）。
2. **提取准确，不失真**：基于代码、注释和 README，必须标注信息来源。
3. **输出标准，可直接流转**：严格按照固定格式输出 `DELIVERY_PACKAGE.md` 及附件。
4. **识别已知问题，不隐藏**：主动扫描并列出 TODO、FIXME、硬编码及潜在技术债。
5. **平台无关，可复用**：不绑定特定技术栈，适用于任何软件工程项目。

## 4. 执行流程（五步法）

当收到触发词 `提取系统交付包` 时，AI 必须自主执行以下五步：

### Step 1: 环境与范围确认
- 确认当前所在的项目工作空间（如：番医饭堂点餐系统）。
- 扫描项目根目录，识别技术栈（如：前端 Vue/React，后端 Node/Python，数据库 MySQL/PostgreSQL）。

### Step 2: 核心资产提取
- **代码本体**：提取核心业务逻辑文件（路由、控制器、服务层）。
- **数据结构**：提取数据库 Schema、ORM 模型或数据字典。
- **开发历史**：提取 Git 提交记录（最近 10-20 条关键记录）。

### Step 3: 状态与问题扫描
- 扫描项目中的 `TODO`、`FIXME` 标记。
- 识别明显的硬编码（Hardcode）或未处理的异常捕获。
- 记录当前系统的运行状态（如：能否正常启动、有哪些报错）。

### Step 4: 组装交付包 (DELIVERY_PACKAGE)
- 按照第 5 节的格式规范，生成 `DELIVERY_PACKAGE_[项目代号]_[日期].md`。
- 将提取的详细数据（如完整的 Schema、长篇代码）保存为附件。

### Step 5: 交付与流转提示
- 向用户输出提取完成的提示。
- 提示用户下一步可使用 `全面审查 [项目代号]` 进入 VERIFY 阶段。

## 5. 输出格式规范

提取完成后，必须生成以下文件结构：

**主文件**：`DELIVERY_PACKAGE_[项目代号]_[YYYYMMDD].md`
内容结构如下：
```markdown
# [项目名称] - 系统交付包

## 1. 基础信息
- 项目代号：
- 提取日期：
- 技术栈概述：

## 2. 核心业务逻辑
- [简述系统实现的核心业务流程]

## 3. 数据结构概览
- [列出核心数据表及关联关系，详细见附件]

## 4. 已知问题与技术债
- [列出扫描到的 TODO/FIXME]
- [列出硬编码或潜在风险]

## 5. 附件清单
- `schema.sql` (或对应的模型定义文件)
- `api_list.md` (接口清单)
- `git_log.txt` (近期提交记录)
```

## 6. 实战使用指南（以“番医饭堂”为例）

**场景**：同事已搭建完成“番医饭堂点餐系统”，需要用 IS_GENESIS 流程进行第一次实战验证。

**操作步骤**：
1. **进入对应工作空间**：在 Manus 平台进入“番医饭堂”项目的专属对话组。
2. **触发提取**：向 AI 发送指令：`提取系统交付包`。
3. **AI 自主执行**：AI 将自动读取该项目的代码库，执行上述五步流程。
4. **获取结果**：AI 将生成 `DELIVERY_PACKAGE_番医饭堂_[当前日期].md` 及相关附件。
5. **进入下一阶段**：确认交付包无误后，发送指令 `全面审查 番医饭堂`，触发 `IS_GENESIS_VERIFY_SKILL` 进行审查。
