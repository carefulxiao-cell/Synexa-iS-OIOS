## 一、全局阻塞项板块（Global Blockers）

### 1.1 定位

全局阻塞项板块是体系内所有活跃项目的阻塞状态汇总视图，目标是让决策者在一个界面内看清「当前哪些事情卡住了、卡在哪里、谁来解决」，并支持快速推进。

### 1.2 卡片结构

每个阻塞项以卡片形式展示，包含以下字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| **阻塞标题** | 文本 | 一句话描述阻塞内容，例如「NexFlow V3.0 数据库迁移方案未确认」 |
| **归属项目** | 选择 | 关联到具体项目（如 iS-NexFlow / 番医项目 / iS-Synexa 等） |
| **归属引擎** | 选择 | NexFlow / Nex2U / NexChef / Nexsply / NexMPC / NexFA / iS-Synexa |
| **阻塞类型** | 标签 | 决策待定 / 资源缺失 / 外部依赖 / 技术问题 / 信息不足 |
| **严重程度** | 标签 | 🔴 严重阻断 / 🟡 影响进度 / 🟢 低优先级 |
| **负责人** | 文本 | 人名或角色（如「iS-Core 裁决」「执行框推进」） |
| **创建时间** | 日期 | 自动记录 |
| **目标解决时间** | 日期 | 可选填 |
| **当前状态** | 标签 | 待处理 / 处理中 / 已解决 / 已搁置 |
| **备注/进展** | 富文本 | 可追加更新记录，保留历史 |

### 1.3 交互设计

- **AI 模糊输入**：支持自然语言描述阻塞内容，AI 自动解析并填充结构化字段（归属项目、类型、严重程度），用户确认或修改后保存
- **人工修改**：所有字段均可直接编辑
- **卡片视图**：默认按严重程度排序，支持按项目/引擎/状态筛选
- **列表视图**：支持表格形式查看，便于批量处理
- **状态流转**：待处理 → 处理中 → 已解决，每次流转可附加备注
- **通报生成**：选中若干卡片，一键生成「阻塞项通报」文本，可直接发送至对应工作空间

### 1.4 与 GitHub 的同步关系

- 阻塞项解决后，系统自动提示「是否同步更新 CONTEXT_OS.md 或对应 PCS 文件」
- 重大阻塞项（🔴 严重阻断）解决后，强制触发 iS-Core 状态回写提醒

## 二、关键决策日志板块（Decision Log）

### 2.1 定位

关键决策日志是体系内所有重大裁决的结构化存档，目标是让任何时间接入的智能体或协作者，都能快速理解「过去做了哪些决策、为什么、影响了什么」，避免重复讨论已定事项。

### 2.2 卡片结构

每条决策记录以卡片形式展示，包含以下字段：

| 字段 | 类型 | 说明 |
|---|---|---|
| **决策标题** | 文本 | 一句话描述决策内容，例如「引擎体系由四大扩展为七大」 |
| **决策日期** | 日期 | 裁决发生日期 |
| **裁决主体** | 选择 | iS-Core / iS-SCO / 具体项目组 |
| **影响范围** | 标签 | 全局体系 / 具体引擎 / 具体项目 |
| **决策背景** | 富文本 | 为什么做这个决策，触发原因 |
| **决策内容** | 富文本 | 具体裁决结果，可分条列出 |
| **影响文件** | 文本 | 需要同步更新的文件列表（如 CONTEXT_OS.md / PCS 文件） |
| **执行状态** | 标签 | 已回写 / 待回写 / 部分回写 |
| **备注** | 富文本 | 后续补充说明、执行情况更新 |

### 2.3 交互设计

- **卡片视图**：默认按日期倒序，支持按影响范围/裁决主体/执行状态筛选
- **详情页**：点击卡片进入详情，支持编辑备注、更新执行状态、查看历史修改记录
- **通报生成**：选中决策卡片，一键生成「决策通报」文本，可发送至对应工作空间或 GitHub commit message
- **回写提醒**：执行状态为「待回写」的卡片，在首页显示提醒角标
- **搜索**：支持全文搜索决策内容

### 2.4 与 GitHub 的同步关系

- 新增决策时，系统提示「是否同步写入 CONTEXT_OS.md 决策日志」
- 执行状态改为「已回写」时，记录对应 GitHub commit hash，作为溯源依据

## 三、两个板块的协同关系

阻塞项与决策日志之间存在关联：

- 一个阻塞项被解决，往往对应一条决策记录（例如「Nex2U/NexChef 架构关系」的阻塞，对应「2026-04-26 架构裁决」的决策）
- 系统支持在阻塞项卡片中「关联决策」，反之亦然
- 这样形成完整的「问题 → 决策 → 执行」闭环追踪

## 四、开发优先级建议

| 模块 | 优先级 | 理由 |
|---|---|---|
| 阻塞项板块（基础版：卡片 CRUD + 筛选） | P0 | 当前体系最迫切的需求，直接影响推进效率 |
| 决策日志板块（基础版：卡片 CRUD + 筛选） | P0 | 与 CONTEXT_OS 决策日志对应，防止信息停留在聊天记录 |
| AI 模糊输入（阻塞项） | P1 | 降低录入门槛，提升更新频率 |
| 通报生成 | P1 | 与现有工作流（ISYNC 通报机制）对接 |
| GitHub 同步提醒 | P2 | 辅助功能，手动操作可替代 |
| 阻塞项与决策的关联 | P2 | 闭环追踪，待基础版稳定后再加 |
