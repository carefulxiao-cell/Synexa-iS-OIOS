# FoodCard 生产标准规范
> Synexa FoodCard Skill V.1.5

## 0. 触发与执行约定

- **触发条件**：用户发送 SOP 截图 + 关键词「FoodCard」。
- **执行方式**：收到即执行，无需确认，直接输出完整 FoodCard 文字内容。
- **模块归属**：由 Agent 基于食材与节气自动判断，用户有异议时事后反馈覆盖。
- **日期**：默认使用当天日期（公历 + 农历），用户未特别说明时不询问。

---

## 1. 工作流程与责任边界

采用「人工定规输入 → 机器智能计算 → AI 语义生成」的协同模式。

- **人工（User）提供**：SOP 截图（含食材、用量g、规格、做法、定价）。
- **Agent 负责**：
  1. 精确提取 SOP 数据。
  2. 基于《中国食物成分表》计算 14 项营养素含量与 Ref.%。
  3. 基于知识库生成食材特点、洞察文案、适宜/禁忌人群。
  4. 严格按照【标准输出结构】组装并交付 Markdown 文档。

## 2. 核心规则（固定逻辑）

### 2.1 模块归属判断逻辑
从以下 5 个模块中选 1 个，判断依据为食材功效与当前节气：

| 模块 | 判断依据 |
| :--- | :--- |
| **顺时食养** | 主打应季食材、顺应当前节气（如立秋清润、盛夏消暑） |
| **功能调衡** | 主打特定机能调节（如健脾开胃、化痰止咳、利湿祛浊） |
| **补元养护** | 主打气血两虚、大病初愈、虚弱体质的温补（高蛋白、高营养密度） |
| **身心舒养** | 主打安神、助眠、舒缓情绪、减压 |
| **+关怀定制** | 特殊病种或个性化需求的特殊餐 |

### 2.2 营养计算与颜色标注原则
依据《中国食物成分表》按实际用量（g）加权计算，NRV 参考 GB 28050。
输出营养表格时必须包含「标注色」列：

| 颜色 | 适用项目 | 判断逻辑 |
| :--- | :--- | :--- |
| **绿色** | 优质补充项 | Ref.% ≥ 20%，且属于需主动补充的营养素（蛋白质、膳食纤维、钾、钙、镁、磷、铁、锌） |
| **橙色** | 控制项 | 胆固醇、钠、糖（天然来源）——**无论 Ref.% 高低，均标橙色** |
| **黑色** | 一般参考项 | Ref.% 在 8%~19% 之间 |
| **灰色** | 可忽视项 | Ref.% ≤ 7% |

### 2.3 食材 Emoji 匹配规则
- 每种食材前配 1 个 Emoji，优先选形态/颜色相近的具象图标。
- 若无精准图标，按颜色系匹配（如 🍒 红色果实代指山楂，🫘 棕色种子代指红枣）。
- 描述文案风格固定为：「富含…，常用于…」的功能性表达，避免纯成分罗列。

## 3. 标准输出结构（8 个区块）

### 【顶部区块】
- 模块标识（中文名 + 英文名）
- 模块导航栏（√ 标注当前模块，其余四个并列）
- 日期（节气标签 ｜ 功效标签 / 公历 / 农历）

### 【核心洞察区块】
- 节气/场景背景文字（两行：环境痛点 + 本品应对逻辑）
- 副标题（`[节气]食养 ｜ [四字核心功效]`）

### 【产品主标题区块】
- 节气/场景推荐标签
- 产品名称（分行大字）

### 【食材与食养特点表格】
格式：`| [Emoji] [食材名] | 富含…，常用于… |`

### 【营养成分表】
- 声明行：数据依据《中国食物成分表》加权计算，NRV 参考 GB 28050。
- 表头：`| 项目 | 含量（约） | Ref.% | 标注色 |`
- 固定 14 项：能量、蛋白质、脂肪、碳水化合物、膳食纤维、糖、胆固醇、钠、钾、钙、镁、磷、铁、锌。

### 【营养设计说明】
固定三条（第②条中括号内替换为当前节气）：
> ① 依据《中国居民膳食指南（2022）》倡导的食物多样、优质蛋白、合理烹调原则设计；
> ② 结合岭南[节气/季节]饮食特点，采用当季食材进行搭配；
> ③ 为健康膳食组成部分，不替代疾病治疗；特殊疾病患者请遵医生或营养师建议。

### 【底部适宜人群区块】
- **宜（绿色区域）**：适合人群及场景（1行）+ ⭐ 核心标签（4个短词）
- **忌（橙色区域）**：⚠ 不建议人群（过敏原 + 特定成分限制 + 特殊医嘱）

### 【SOP 留档】
还原 SOP 原始表格、做法步骤、定价。
