## 一、并行工作线设计

2周内完成 MVP 的关键，是将原本串行的工作拆分为三条可并行推进的工作线，通过"API 契约"作为接口，使各线互不阻塞。

| 工作线 | 负责范围 | 主要工具 | 可并行启动时间 |
| :--- | :--- | :--- | :--- |
| **线 A：引擎与数据** | Nex₂U 核心引擎 + 六大数据库 Schema + 基础数据录入 | Manus / GPT / Code | Day 3（契约完成后） |
| **线 B：前端（Nufō³）** | H5 点餐界面重构对接，基于 Mock 数据并行开发 | Manus / Code | Day 3（契约完成后） |
| **线 C：后台（NuBō）** | 运营管理后台重构，实现六大数据库的管理界面 | Manus / Code | Day 3（契约完成后） |

> **解耦机制**：Day 1-2 完成"API 契约文档"，之后三线同时启动。线 B 和线 C 使用 Mock 数据开发，不等待线 A 的引擎完成。

## 四、GPT 同步提醒机制说明

**你的问题**：GPT 同步提醒，指的是 GitHub 上有新文件？还是有文件被更新？

**答**：两种情况都需要同步，原因如下：

GPT Project 的知识库（Files）是**静态上传**的，它不会自动读取 GitHub 的最新版本。每次 GitHub 上的文件发生变化（无论是新增还是更新），GPT 侧都不会自动感知，必须**手动重新上传**。

| 触发情况 | 是否需要同步 GPT | 说明 |
| :--- | :--- | :--- |
| GitHub 新增了一个文件 | ✅ 需要 | GPT 知识库里没有这个文件，需要上传 |
| GitHub 更新了一个已有文件 | ✅ 需要 | GPT 知识库里的是旧版本，需要重新上传覆盖 |
| GitHub 删除了一个文件 | ⚠️ 建议 | GPT 知识库里的旧文件会造成认知混乱，建议删除 |

**Manus 侧**则不同：Manus 通过 GitHub MCP 连接器，每次对话都可以实时读取仓库最新内容，不需要手动同步。这也是 Manus 在执行层更高效的原因。

**简单记法**：
- **Manus = 实时读 GitHub**（自动对齐）
- **GPT = 读上传的文件**（需手动同步）
