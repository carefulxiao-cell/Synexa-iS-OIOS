## 一、工作空间分类体系与分工逻辑

Synexa iS 体系下共设六类 AI 工作空间，各有明确的职责边界与触发条件。

| # | 中文名 | 英文代号 | 职能比喻 | 职能一句话 | SSADS 层级 |
| :--- | :--- | :--- | :--- | :--- | :--- |
| 1 | **智核中枢** | `iS-Core` | 董事会 | 基线治理 · 项目孵化与裁决 | L1·治认中枢 |
| 2 | **智权枢纽** | `iS-Hub` | 情报室 | 智能体资源库 · 内外部 Agent 案例、工具与平台的汇聚与参照 | L1·治认中枢（延伸） |
| 3 | **枢机经纬** | `iS-SCO` | 策略室 | 推演辅助 · 战略推演与决策支持（N·Grid / EKB） | L2·知识推演 |
| 4 | **智核矩阵** | `iS-Matrix` | 研究培训室 | 结构化产出引擎 · SOP / 规程 / 模板 / 数字员工指令的生产与固化 | L3·技能规程 |
| 5 | **各 PCS 项目** | `iS-[代号]` | 项目组 | 具体项目全生命周期推进 | L5·项目执行 |
| 6 | **智核实验场** | `iS-Lab` | 灵感前测室 | 灵感容器 · 未成熟想法的最小验证场 | L1·治认中枢（前置缓冲） |

> **关于 SOP 的定位说明**：SOP 不是独立的工作空间类型，而是 `iS-Matrix` 的核心产出类型之一。SOP 文件存放于 GitHub `05-sop/` 目录，是所有工作空间的规程权威来源。

> **关于超智（Synexa）的定位说明**：Synexa 体系由四层构成——Brand Layer（超智品牌）→ System Layer（Synexa iS 智能系统基座）→ Module Layer（iS Modules 智核模块体系，即本文件所定义的六类工作空间）→ Engine Layer（Nex 业务引擎体系）。六类工作空间属于 Module Layer，是 Synexa iS 的功能单元。所有收入与市场发生在 Nex 层，iS 层只提供能力与调度，不直接产生收入。完整定义见 `00-overview/Synexa_Architecture_Definition_v1.1.md`。

## 二、核心运作闭环与协作规程

体系的知识生产与固化遵循以下五节点闭环，这是整个体系持续进化的核心机制：

```
iS-SCO · 策略室（推演研究）
    ↓ 推演结论 → 提交基线更新
iS-Core · 董事会（基线裁决）
    ↓ 更新共识 / 下达生产指令 → 写入 CONTEXT_OS + GitHub
iS-Matrix · 研究培训室（结构化生产）
    ↓ 产出 SOP / 规程 / 模板 / 指令 → 回写 GitHub 05-sop/
iS-[PCS] · 项目组（执行落地）
    ↓ 执行中发现问题 / 产生新认知 → 反馈
iS-SCO · 策略室（新一轮推演）
    ↓ 循环
```

**此闭环的意义**：每一条 SOP 都有推演来源，每一次执行都在反哺推演，知识不会在对话里消散，而是持续沉淀为可调用的体系资产，并可对外传递与赋能。

## 三、各工作空间职责边界与触发/停止机制

### 3.1 智核中枢（iS-Core）· 董事会

**职责（只做这四件事）**：
1. 识别是否需要新项目（判断触发条件）
2. 完成最小定义（Step 0A 级别：项目名称、一句话定义、层级归位、优先级）
3. 做项目归位（G·集团级 / B·业务线级 / F·功能模块级）
4. 确认优先级（与现有活跃项目的关系与排序）

**停止边界**：
> 一旦完成最小定义，iS-Core 必须立即停止深入讨论，不得在中枢层继续推进该项目的业务细节、执行方案或内容设计。

**触发动作**：
> 最小定义完成 → 立即创建该项目的 PCS → 后续所有推进转移至该项目专属对话组进行。

---

### 3.2 智权枢纽（iS-Hub）· 情报室

**职责**：
- 汇聚内外部智能体（Agent）案例、工具与平台信息
- 对外信息接口及清洗，评估外部工具的可用性
- 维护体系的"智能体能力地图"与选型建议

**与 Matrix 的边界**：
> iS-Hub 负责"向外看"（收录、评估、参考）；iS-Matrix 负责"向内建"（生产、固化、部署我们自己的 Agent 指令）。

---

### 3.3 枢机经纬（iS-SCO）· 策略室

**职责**：
- 战略推演与期望值计算（N·Grid 框架）
- 重大决策的风险揭示与反向验证（RVM）
- 成本对冲量化（CCM）
- 内含 EKB（知算善衡）等具体推演工具

**在闭环中的角色**：闭环的起点与终点，负责将执行经验转化为新的推演命题，驱动体系持续进化。

---

### 3.4 智核矩阵（iS-Matrix）· 研究培训室

**职责**：
- 接收来自 iS-Core 的生产指令
- 生产 SOP、操作规程、标准模板、数字员工指令等结构化文档资产
- 将产出回写至 GitHub `05-sop/` 目录
- 管理数字员工矩阵的能力定义与迭代

**关于 SOP 的说明**：SOP 是 iS-Matrix 的核心产出类型，不是独立的工作空间。iS-Matrix 是"生产车间"，`05-sop/` 是"成品仓库"，两者配合运作。

---

### 3.5 各 PCS 项目（iS-[代号]）· 项目组

**职责**：
- 单一项目的全生命周期推进（Step 1 → Step 6）
- 项目内所有任务的执行与状态管理
- 项目产出的回写与归档
- 执行中发现的问题与新认知，反馈至 iS-SCO 触发新一轮推演

**当前已立项的 PCS 实例**：

| 项目名称 | 代号 | 当前状态 |
| :--- | :--- | :--- |
| 超智建设 | `iS-Synexa` | 🟡 已立项 · Step 0B（待推进） |
| 智食引擎 | `iS-Nex2U` | Step 3 推进中 |
| 意臻供应链 | `iS-Nexsply` | 待立项 |
| NexChef（待定） | `iS-NexChef` | 持续运营，项目名称待确认 |

---

### 3.6 智核实验场（iS-Lab）· 灵感前测室

**职责**：
- 接住未成熟的想法与业务苗头
- 做最小可行性验证（不超过 Step 0A）
- 判断是否值得提交 iS-Core 正式立项

**停止边界**：
> iS-Lab 不得自行推进任何项目超过最小验证阶段。一旦判断值得立项，必须提交至 iS-Core 完成正式孵化流程。

## 四、越界提示机制

当用户在某个工作空间提出的请求超出该空间的职责边界时，AI 必须暂停执行，输出标准提示：

```
⚠️ 越界提示
你当前的请求「[请求摘要]」超出了本工作空间（iS-[代号] · [职能比喻]）的职责范围。
建议转移至：iS-[目标代号]（[目标空间名称] · [职能比喻]）处理。
是否确认在此继续？若确认，本次执行标注为 [非标执行·已越界]。
```

**坚持继续的处理**：AI 执行，但在输出末尾标注 `[非标执行·已越界]`，并在下一次状态回写时记录该事件，供后续流程优化参考。

## 五、工作空间交互规则与决策树

```
我有一个想法 / 任务 / 问题，应该去哪里？

├── 是新想法或新业务苗头，还不确定要不要做
│   └── → iS-Lab（灵感前测室）做最小验证
│           └── 验证后值得推进 → 提交 iS-Core 正式立项

├── 需要判断是否立项 / 完成项目最小定义 / 裁决基线共识
│   └── → iS-Core（董事会）

├── 有具体项目任务要推进
│   └── → 对应的 iS-[项目代号]（项目组）

├── 发现外部好用的 Agent 工具或案例，需要评估收录
│   └── → iS-Hub（情报室）

├── 需要做重大决策 / 战略推演 / 风险评估
│   └── → iS-SCO（策略室）

└── 需要生产 SOP / 规程 / 模板 / 数字员工指令
    └── → iS-Matrix（研究培训室）
```

## 六、跨平台指令同步机制

### 6.1 指令文件结构（GitHub SSOT）

```
00-overview/
├── AI_Workspace_Architecture_v1.3.md   ← 本文件（工作空间架构总说明）
├── Manus_Project_Instructions_v[版本].md  ← Manus 侧指令母本
├── GPT_Project_Instructions_[版本].md     ← GPT 侧指令母本
└── instructions/                          ← 各工作空间专属指令目录
    ├── iS-Core_Instructions.md
    ├── iS-Hub_Instructions.md
    └── ...
```

### 6.2 Manus 侧同步机制

Manus 具备 GitHub 直连能力，每次对话自动拉取最新版本，**无需手动更新 Project 指令**。

### 6.3 GPT 侧同步机制（主动盯紧）

GPT 无法直连 GitHub，采用以下机制确保同步不漏：

**触发提醒**：每次 GitHub 有文件更新，Manus 在回复末尾附加 GPT 同步提醒，列明需要上传的文件清单。

**盯紧机制**：触发同步提醒后，AI 不得在同一对话中继续推进新任务，直到收到以下任一确认信号：
- 用户回复"已更新"或"已上传" → AI 将对应文件状态标记为 `✅ 已同步`
- 用户回复"暂缓，稍后处理" → AI 记录为待同步事项，**下次对话开头主动追问**
- 用户回复"跳过本次" → AI 记录为已知版本差异，不再追问

**待同步事项追踪**：在 `CONTEXT_OS.md` 的「待同步事项」字段中持续记录，每次接入必须检查并置顶提示。
