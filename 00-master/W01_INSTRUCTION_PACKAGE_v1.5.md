## 一、任务目标（TBF）

构建 Synexa iS 体系的全局枢纽系统，以全局架构图为导航主界面，将 GitHub 仓库中的治理文件结构化呈现，支持节点交互、详情卡片查阅、AI 辅助录入与内容导出，并配备账号体系、草稿协作机制、全局阻塞项管理与关键决策日志。

**一句话定义**：让 Synexa iS 体系的治理内容从静态文件变成可交互、可查阅、可录入、可追踪的在线全局枢纽。

> **定位说明**：本系统是 NexFlow 在超智体系内部的自用实例，承载 NexFlow 产品能力的内部验证场。归属 NexFlow·Synexa 项目，执行框代号「执行-智核中枢·iS-Core」。

## 二、MVP 交付标准

### 2.1 主页 · 架构图导航

**【强制约束，最高优先级】**

- 主画布**必须直接使用 `00-master/SYNEXA_GLOBAL_ARCHITECTURE_v1.3.png` 原图作为底图**
- **禁止自行重绘或重新生成架构图**
- 在原图上叠加透明交互热区（每个节点对应一个可点击/悬停区域）
- 热区坐标必须基于原图中各节点的**实际像素位置精确标注**，不能估算
- 视觉效果必须与原 PNG 完全一致，白底，不做任何样式改动

**鼠标悬停节点** → 浮出 Tooltip 气泡卡片，展示：
- 框名称 + 层级归属
- 一句话定义（职能简述）
- 框类型（中枢框 / 执行框 / 编撰框 / 审查框）
- 当前状态（活跃 / 待建立 / 暂停）
- 关联文件清单（可滚动）
- 关联机制（机制代号）
- 触发词列表
- 底部引导：「点击查看完整详情 →」

**点击节点** → 跳转至该节点的详情页

### 2.2 详情页 · 结构化卡片

每个节点详情页包含以下模块：

| 模块 | 内容 |
| :--- | :--- |
| 基本信息 | 框名称 / 代号 / 层级 / 框类型 / 当前状态 |
| 职能定义 | 一句话定义 + 职能边界（做什么 / 不做什么） |
| 关联文件 | 该节点对应的文件清单（可点击查看文件内容） |
| 关联机制 | 涉及的机制（ISYNC / TBF / SOP 系列等） |
| 触发词 | 在该框内生效的触发词列表 |
| 指令清单 | 当前有效指令摘要（可展开查看完整内容） |
| 推进状态 | 当前活跃任务 / 最近更新 / 阻塞项 |
| 操作区 | 新增条目 / 导出 / 提交草稿 |

### 2.3 账号体系

- 登录方式：账号密码（沿用 NexFlow 模式）
- 三级角色：
  - **超管**：全部权限（新增、编辑、审核合并、用户管理、排序调整）
  - **项管**：可新增草稿、提交审核，不可直接合并
  - **成员**：只读 + 提交草稿

### 2.4 新增录入（AI 辅助对齐）

- 入口：详情页操作区「新增条目」按钮
- 流程：
  1. 用户输入非结构化文字（模糊描述、想法片段）
  2. AI 自动对齐为标准卡片字段（调用 LLM API，使用 `gpt-4.1-mini`）
  3. 用户确认或手动修改字段
  4. 提交草稿 → 管理员审核 → 并入 GitHub 仓库

### 2.5 协作模式（一阶段）

- 多人可读：所有角色均可查阅全部内容
- 草稿提交：项管/成员可提交草稿，不直接写入
- 管理员审核合并：超管审核通过后，内容写入 GitHub 并更新展示
- 实时块级协同编辑：不在本期范围，放二阶段

### 2.6 数据导出

- 支持格式：Markdown / JSON
- 导出范围：单个卡片 / 整个板块 / 全量导出

## 四、全局阻塞项板块规格

### 4.1 卡片字段

| 字段 | 类型 | 说明 |
|---|---|---|
| 阻塞标题 | 文本 | 一句话描述阻塞内容 |
| 归属项目 | 选择 | 关联到具体项目 |
| 归属引擎 | 选择 | NexFlow / Nex2U / NexChef / Nexsply / NexMPC / NexFA / iS-Synexa |
| 阻塞类型 | 标签 | 决策待定 / 资源缺失 / 外部依赖 / 技术问题 / 信息不足 |
| 严重程度 | 标签 | 🔴 严重阻断 / 🟡 影响进度 / 🟢 低优先级 |
| 负责人 | 文本 | 人名或角色 |
| 创建时间 | 日期 | 自动记录 |
| 目标解决时间 | 日期 | 可选填 |
| 当前状态 | 标签 | 待处理 / 处理中 / 已解决 / 已搁置 |
| 备注/进展 | 富文本 | 可追加更新记录，保留历史 |

### 4.2 交互设计

- **AI 模糊输入**：支持自然语言描述，AI 自动解析并填充结构化字段，用户确认或修改后保存
- **人工修改**：所有字段均可直接编辑
- **卡片视图**：默认按严重程度排序，支持按项目/引擎/状态筛选
- **列表视图**：支持表格形式查看，便于批量处理
- **状态流转**：待处理 → 处理中 → 已解决，每次流转可附加备注
- **通报生成**：选中若干卡片，一键生成「阻塞项通报」文本

## 五、关键决策日志板块规格

### 5.1 卡片字段

| 字段 | 类型 | 说明 |
|---|---|---|
| 决策标题 | 文本 | 一句话描述决策内容 |
| 决策日期 | 日期 | 裁决发生日期 |
| 裁决主体 | 选择 | iS-Core / iS-SCO / 具体项目组 |
| 影响范围 | 标签 | 全局体系 / 具体引擎 / 具体项目 |
| 决策背景 | 富文本 | 触发原因 |
| 决策内容 | 富文本 | 具体裁决结果，可分条列出 |
| 影响文件 | 文本 | 需要同步更新的文件列表 |
| 执行状态 | 标签 | 已回写 / 待回写 / 部分回写 |
| 备注 | 富文本 | 后续补充说明、执行情况更新 |

### 5.2 交互设计

- **卡片视图**：默认按日期倒序，支持按影响范围/裁决主体/执行状态筛选
- **详情页**：点击卡片进入详情，支持编辑备注、更新执行状态、查看历史修改记录
- **通报生成**：选中决策卡片，一键生成「决策通报」文本
- **回写提醒**：执行状态为「待回写」的卡片，在首页显示提醒角标
- **搜索**：支持全文搜索

### 5.3 阻塞项与决策日志的关联

- 阻塞项卡片支持「关联决策」字段，指向对应的决策记录
- 形成「问题 → 决策 → 执行」完整闭环追踪

## 六、对话组管理板块结构（v1.2 · 数据源更新）

**数据来源**：`WORKSPACE_REGISTRY_v2.0.md`（已入库，直接读取渲染）

**三层结构：**

```
顶层（全局级别分类）
  ├─ L1 · 全局枢纽（G-LEVEL）
  ├─ L2 · 核心业务引擎（BUSINESS SYSTEMS）
  ├─ L3 · 垂直场景与应用项目（VERTICAL PROJECTS）
  └─ L4 · 独立探索（EXPERIMENTAL）
      ↓ 展开
一级：项目组（如 iS-Core / NexFlow / Nex2U 等）
      ↓ 展开
二级：框类型分组（中枢框 → 执行框 → 编撰框 → 审查框 → 讨论框）
      ↓ 点击卡片
对话框详情管理页（定位 / 职能边界 / 关联文件 / 机制 / 触发词 / 指令清单 / 推进状态 / 操作区）
```

**排序规则：**
- 顶层分类顺序固定（L1 → L2 → L3 → L4）
- 项目组内框类型顺序固定（中枢框置顶，其余按执行→编撰→审查→讨论）
- 超管可手动调整同层级内排列顺序

## 七、各板块卡片规范

**机制汇总 / 触发词汇总 / 指令清单 统一规范：**
- 布局：**单列向下滚动**（不使用两列网格）
- 卡片顶部：`英文代号 · 中文名称`（中英文并列，如 `ISYNC · 全局指令同步协议`）
- 卡片中部简略标签：触发词 / 协议文件 / 状态
- 卡片右侧：状态 badge（已启用 / 待建立 / 已升级）
- 卡片底部：「点击查看详情」
