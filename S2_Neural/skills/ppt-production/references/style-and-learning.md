# 风格变量与经验状态

## 当前用户偏好配置

明确偏好：减少蓝色占比；白底、硬朗、充分留白；主标题尽量短、单行并最大化；标题、标签、图形、共享底座、分隔线等构件标准化。强调自身特点，不用无依据的竞品或成果对比。

这些偏好作为当前用户的起点；具体项目品牌色、字号、比例、图像与轮廓仍由素材和观看场景适配。当前意臻案例以绿紫少量强调，未将本轮具体字号或图片处理写成用户永久认可参数。

## 一、品牌配置不写死

每个项目分别建立品牌配置：

| 变量 | 应记录什么 |
| --- | --- |
| 品牌来源 | 用户指定文件、标识及其版本 |
| 主色与辅色 | 角色、比例及必要可读性调整，不只保存HEX |
| 中文／拉丁／数字字体 | 实际字形支持、字重、替代及导出显示 |
| 标题层级 | 结论标题、模块标题、正文、边界与页脚的相对关系 |
| 标签与分隔线 | 位置、形态、用途，避免每页随意变化 |
| 间距与对齐 | 共同基线、内边距、列距及图文间隔 |
| 图片语言 | 真实／概念、器皿、光线、角度与表现边界 |
| 数据语言 | 数字、单位、区间、估算与报价属性的组织 |
| 验证状态 | 用户明确／候选／已确认／已应用验证 |

继承品牌不等于继承其所有信息密度。借鉴参考不等于继承其原品牌色。字体、间距、位置可以统一；页内的空间组织应匹配各自内容。

## 二、经验状态

| 状态 | 定义 | 能否作为后续默认 |
| --- | --- | --- |
| 明确约束 | 用户明确要求的范围、格式与边界 | 可在相同授权和项目内沿用 |
| 候选方法 | 设计分析推导、尚未获用户评价 | 仅作建议，不称已确认 |
| 用户已确认 | 用户对方案或样页明确认可 | 在约定适用范围内沿用 |
| 应用已验证 | 经实际导出、使用反馈或重复应用验证 | 记录情境后沉淀为可复用经验 |
| 需修正 | 用户否定或实际使用暴露问题 | 作为反例，不继续默认套用 |

工具结构检查通过只说明文件结构，不能替代用户的审美评价。用户确认整体方向，也不意味着每个字体尺寸、图像处理和细线参数都永久锁定。

## 三、迭代记录格式

采用简短条目，不保存全部对话：

- 日期／版本：
- 问题与场景：
- 采用的方法：
- 用户反馈或实际观察：
- 当前状态：
- 适用边界：
- 下一次如何验证：

只把真正有迁移价值的判断写入主skill；具体案例的价格、面积、页数、临床条件和截图编号留在案例文件。

## 四、可读性与风格验收

- 先判断页面主任务是否清楚，再看其是否精致。
- 一次观察实际页面和全套缩略节奏，避免只验证漂亮封面。
- 检查字幕、限制与单位在实际观看尺寸是否清楚，而非仅在编辑窗口放大后可读。
- 不把淡色小字、美观但错误的比例、无意义装饰关系或模糊的单位当作高级感。
- 不用“无溢出”代替“关系易懂”，也不因用户喜欢某张参考就复制其全部元素。
- 改稿前保护源文件；范围清楚时执行，用户要求分阶段确认时遵守，不把分析任务扩为工程。

## 五、可编辑性修复经验｜2026-11-22／v1.1.0

- 问题与场景：旧演示稿可能同时存在整页装饰位图与独立文字；外观可读不等于构件可编辑。
- 采用的方法：先做对象与画面的对应检查，保留可用原生对象，按指定外观重建底图中的装饰；详细流程见 `editability-repair.md`。
- 用户反馈或实际观察：用户要求色块、线、点、边框可单独选中修改，并明确要求将该经验补入skill。
- 当前状态：方法约束已获用户明确授权；案例对象检查已完成；修复后的导出、应用兼容及用户视觉评价尚未完成。
- 适用边界：可编辑PPT修复及跨格式转换；不把所有背景图片视为错误，不借修复授权改写内容或改变风格。
- 下一次如何验证：在实际导出稿核查逐页对象覆盖和代表性编辑操作，再检查渲染与指定应用；具体案例事实见 `case-nexsply-editability.md`。
