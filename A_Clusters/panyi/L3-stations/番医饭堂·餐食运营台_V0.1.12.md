## 1. 工作台定位

番医饭堂餐食运营推进工作台用于把“餐食结构运营中台”的复杂链路拆成可执行工作面：

场景线 → 终端菜单 → 产品 SKU → 结构点池 → 结构点 SKU → 食材 SKU → BOM → SOP → 菜单模型 → 采购模型 → 生产配送 → 营收营利 → 复盘。

当前工作台不是菜谱本，也不是单纯文件列表，而是一个运营推进界面：每次打开都应能回答“现在推哪条链路、依赖什么资产、卡在哪里、下一步怎么做、产出写回哪里”。

## 3. 关键字典

说明：本版块只保留“对象边界字典”，避免与“核心工作”的方法论重复。核心工作负责讲推演链路；本字典负责定义每类对象在表格和系统里的边界。

| 分层 | 对象 | 定义 | 边界提醒 |
|---|---|---|---|
| 场景 / 需求层 | 场景线 | 谁吃、在哪吃、按什么产品和服务规则履约。 | 不等于配送路线；同一场景可有多个菜单入口。 |
| 场景 / 需求层 | 人群需求母型 | 某类人群在营养、口味、价格、便利、禁忌、服务上的需求原型。 | 不能直接当产品 SKU；用于校正产品策略和菜单模型。 |
| 现实呈现层 | 终端菜单 | 用户、厨房、院方实际看到的菜单入口。 | 不是最终模型，只是现实入口；需要反推 SKU、结构点和采购。 |
| 销售结算层 | 产品 SKU | 可独立售卖、结算、沟通、上菜单、上系统的产品单位。 | 套餐、加餐菜、粉面、粥、包点、饮品、专项餐都可能是产品 SKU。 |
| 厨房结构层 | 逻辑结构点池 | 产品 SKU 背后的结构池，如大荤、半荤、时蔬、汤羹、主食、加购、专项小炒。 | 不是具体菜名；用于承接轮换、可选、固定和加购逻辑。 |
| 厨房生产层 | 生产结构点 SKU | 厨房最小生产 / 出品任务单位。 | A/B/C/D 套餐不是生产结构点 SKU；套餐内的菜品、主食、汤羹才可能是生产结构点。 |
| 专业健康层 | 营养结构点 | 按健康、营养、禁忌、康复目标划分的结构约束。 | 不替代生产结构点；用于校正菜单和产品策略。 |
| 采购供应层 | 食材 SKU / 采购资源池 | 采购、库存、供应商、替代、成本管理对象。 | 食材 SKU 与生产结构点 SKU 不能混用。 |
| 成本财务层 | BOM / 成本模型 | 结构点 SKU 与食材 SKU、用量、单位、出成率、损耗、单份成本之间的桥。 | 不是单纯菜谱；必须服务成本、采购和毛利判断。 |
| 执行履约层 | SOP / 配送路线 / 标签 | 生产工艺、出品标准、时间节点、温控、标签和送达路径。 | 配送路线回答“送到哪里”，场景线回答“为谁按什么规则服务”。 |
| 经营复盘层 | 营收营利模型 / 规则资产 | 销量、项次、金额、成本、毛利、反馈、异常和下一轮规则。 | 不确定口径必须标注待确认，不能写成已确认事实。 |

|---|---|
| 1. 番医餐食运营中台双向推演链 | 科学总模型：终端菜单 ⇄ 产品 SKU ⇄ 生产结构点 SKU ⇄ 食材 SKU / 采购资源池 ⇄ 成本管理模型 ⇄ 营收营利模型。<br>专业校正模型：人群需求母型 ⇄ 营养结构点 ⇄ 产品 SKU 策略 ⇄ 菜单模型。<br>核心定位：菜单不是孤立菜单，而是销售、厨房、采购、营养、成本、营收共同校正后的运营结果。 |

| 4. 第二条线：设计正推线 | 路径：人群需求母型 → 营养结构点 → 产品 SKU 策略 → 生产结构点 SKU → 菜单模型 → 采购模型 → 成本模型 → 营收营利模型 → 终端菜单。<br>回答：谁吃；为什么吃；需要什么营养、口味、价格和服务；应设计哪些产品；厨房如何承接；采购如何支撑；成本是否合理；最终菜单如何呈现。 |
| 5. 第一阶段：终端菜单结构排布表 | 目标：先把厨房菜单变成可读、可审、可统计的结构化排布。<br>关键要点：按日期、餐别、场景线、产品、结构点池、价格、供应窗口、备注和风险项记录；为后续 SKU 映射和菜单审核提供现实入口。 |
| 6. 第二阶段：产品 SKU × 逻辑结构点池映射表 | 目标：让每个产品 SKU 明确由哪些结构点池支撑。<br>回答：一个产品 SKU 由哪些结构点池组成；结构点池是固定、轮换、可选、加购、赠送还是专项；哪些结构点池跨产品复用；哪些产品缺生产承接；哪些结构点池需要拆细。<br>字段建议：产品 SKU、场景线、价格 / 价格规则、结构点池、结构点池性质、是否每日必须出现、是否影响采购、是否影响生产节点、是否影响体验、是否需人工确认。 |
| 7. 第三阶段：逻辑结构点池 → 生产结构点 SKU | 目标：把结构点池逐步细化为可生产、可排程的结构点 SKU。<br>示例：大荤 / 半荤可拆为清淡主蛋白池、基础猪肉池、基础禽类池、鱼类高风险池；汤羹可拆为免费例汤、经典炖汤、节气汤羹、糖水、半流质羹糊。<br>回答：结构点池下有哪些生产 SKU；哪些已上线、待上、研发；哪些不适合某场景；哪些需要 SOP / BOM。 |
| 8. 第四阶段：生产结构点 SKU → 食材 SKU / 采购资源池 | 目标：从“要生产什么”推到“要采购什么”。<br>回答：每个生产结构点需要哪些主食材；哪些食材高频共用；哪些食材有替代品；哪些受价格、供应、规格、损耗影响大；哪些结构点共用同一采购资源池。 |
| 9. 第五阶段：采购资源池 → 成本管理模型 | 目标：让采购不只是买菜，而是支撑成本、毛利、价格和菜单策略。<br>回答：每个结构点的食材成本带宽、出成率、损耗率、单份成本；产品售价是否合理；哪些产品高感知但成本压力高；哪些产品低价高频但毛利稳定。 |
| 10. 第六阶段：成本管理模型 → 菜单模型 / 采购模型 | 菜单模型回答：每周结构如何排；每天主题如何排；哪些结构点必须稳定出现；哪些轮换；哪些用于营收拉动、体验保底、清淡、节气、营养、地方特色。<br>采购模型回答：日采购怎么预判；周采购怎么计划；固定采购和临时采购怎么分；高风险食材如何备替代；采购量如何根据销量和出品计划调整。 |
| 11. 第七阶段：菜单模型 / 采购模型 → 营收营利模型 | 目标：从菜单和采购回到经营结果。<br>回答：每个产品 SKU 销售数量 / 项次；每个结构点贡献哪些产品营收；哪些菜拉动客单价；哪些菜提高复购；哪些菜成本高但体验必要；哪些菜应保留、降频、替换、研发；菜单策略是否提升营收和满意度。 |
| 12. 第八阶段：复盘回流 | 路径：营收营利模型 → 风险复盘 / 体验反馈 / 规则更新 → 下一轮终端菜单。<br>关键要点：把异常、投诉、销量、毛利、食材波动、生产难度、配送风险转化为下一轮菜单与采购规则。 |
| 13. 推进主链线 × 9 | 终端菜单结构排布表 → 产品 SKU × 逻辑结构点池映射 → 逻辑结构点池 × 生产结构点 SKU → 生产结构点 SKU × 食材 SKU / 采购资源池 → 采购资源池 × 成本管理模型 → 菜单模型 + 采购模型 → 营收营利模型 → 风险复盘 / 体验反馈 / 规则更新 → 下一轮终端菜单。 |
| 14. 专业校正线 | 位置：并列于主链，不插在主链中间。<br>路径：人群需求母型 → 营养结构点 → 产品 SKU 策略 / 结构点池约束 → 菜单模型校正。<br>作用：避免菜单只被成本和销量牵引，补上医院饭堂场景中的人群、营养、康复、禁忌、体验和服务约束。 |
