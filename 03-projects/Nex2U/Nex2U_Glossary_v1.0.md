## 二、业务与产品术语

| 术语 | 定义 | 关键说明 |
| :--- | :--- | :--- |
| **28个主题场景** | T01-T28，覆盖早餐（4）、正餐（21）、加餐（3）的完整餐食主题分类体系 | 四大归属：早餐·启动代谢 / 正餐·工作补能 / 正餐·特殊膳食 / 正餐·慢病管理 / 正餐·功能养生 / 加餐·补能调节 |
| **营养结构点** | 构成一份餐食的最小营养功能单元，编码为 P·C·V·F·PR | P=蛋白质 / C=碳水 / V=蔬菜纤维 / F=脂肪 / PR=特殊功能点（如抗炎、控糖） |
| **90个营养点** | 六维分类下的完整营养点清单，是系统的核心知识资产 | 六维：蛋白 / 碳水 / 脂肪 / 蔬菜纤维 / 控制约束 / 质构 |
| **餐型母型** | 一份餐食的结构模板，定义了营养点的组合比例与位置 | 12个正餐母型 + 7个轻餐母型，是"结构稳定、内容可换"的核心机制 |
| **六大核心数据库** | 支撑引擎运转的六个数据库 | 主题系统 / 母型系统 / 营养点系统 / 工艺规则库 / 食材原料库 / 菜单产品库 |
| **MVP** | Minimum Viable Product，最小可用产品 | 指能跑通核心业务闭环的最精简版本，不追求功能全面 |
| **结构驱动生成** | 通过规则和约束引擎，动态生成符合营养结构的餐食方案，而非人工录入固定菜单 | Nex₂U 区别于传统点餐系统的核心能力 |
| **健康稳态** | 通过持续、结构化的餐食干预，维持人体各项生理指标在健康范围内的长期状态 | 区别于"减肥餐"、"医疗餐"等单一目标，强调长期可持续 |
| **约束引擎** | 处理硬性约束（必须满足）、软性约束（优先推荐）和冲突规则（不能共存）的计算模块 | 是 Nex₂U 引擎层的核心组件 |
| **数据闭环** | 履约数据（用户实际消费、反馈）回流至引擎，用于优化下一次生成规则的机制 | 是系统持续自我迭代的关键 |

## 三、技术架构术语

| 术语 | 定义 | 在本项目的应用 |
| :--- | :--- | :--- |
| **Schema（数据库模式）** | 定义数据库中表结构、字段类型、关系的蓝图 | 开发启动前必须先完成 Schema 设计，是一切的地基 |
| **ER 图（实体关系图）** | 用图形化方式展示数据库中各表（实体）及其关系的设计图 | Node 1 的核心交付物 |
| **API（应用程序接口）** | 系统各层之间通信的标准化接口，定义了"谁能调用什么、传什么参数、返回什么结果" | 前后端分离架构的核心纽带 |
| **RESTful API** | 一种符合 REST 架构风格的 API 设计规范，使用 HTTP 方法（GET/POST/PUT/DELETE）操作资源 | 本项目前后端通信的主要方式 |
| **API 契约** | 前后端开发团队在编写代码前共同约定的 API 接口文档，包含路径、参数、返回值格式 | 防止前后端对接时出现理解偏差的关键文档 |
| **Mock（模拟数据）** | 在后端 API 未开发完成时，前端使用假数据进行开发和测试的技术 | 允许前后端并行开发，不互相等待 |
| **微服务（Microservice）** | 将一个大型系统拆分为多个独立运行、独立部署的小服务 | Nex₂U 引擎应作为独立微服务存在 |
| **前后端分离** | 前端（UI）和后端（API+数据库）独立开发、独立部署的架构模式 | 本项目的基础架构模式 |
| **H5** | 基于 HTML5 标准的移动端网页应用，可在微信内嵌浏览器中运行 | Nufō³ 的主要交付形态 |
| **Vite + React + TailwindCSS** | 本项目前端技术栈：Vite（构建工具）+ React（UI框架）+ TailwindCSS（样式框架） | — |
| **Node.js / Python** | 后端服务的两种候选技术栈 | 引擎层推荐 Python（科学计算友好），管理后台推荐 Node.js |
| **MySQL** | 关系型数据库，用于持久化存储业务数据 | 本项目数据层的主要数据库 |
| **Redis** | 内存数据库，用于缓存高频访问数据（如菜单、营养点规则），提升性能 | 引擎层的性能优化组件 |
| **OSS（对象存储）** | 云端文件存储服务（如阿里云 OSS），用于存储图片、静态资源 | 菜品图片、食材图片的存储方案 |
| **CDN（内容分发网络）** | 将静态资源分发到全球节点，加速用户访问速度 | 前端静态资源的加速方案 |
| **ECS（弹性云服务器）** | 云端虚拟服务器，用于部署后端 API 服务和数据库 | 生产环境的核心基础设施 |
| **HTTPS / SSL 证书** | 加密网站通信的安全协议，是正式上线的必要条件 | 需要为域名申请 SSL 证书 |
| **微信公众平台 / 服务号** | 微信生态的企业账号，用于 H5 页面的 OAuth 授权登录和消息推送 | 用户身份认证的核心渠道 |
| **JSAPI 支付 / Native 支付** | 微信支付的两种方式：JSAPI 用于 H5 内嵌页面，Native 用于扫码支付 | 本项目的双轨支付方案 |
| **飞鹅云打印 API** | 云端小票打印机接口，用于厨房自动出单 | NuBō 执行层的关键硬件接口 |
| **SSOT（单一事实来源）** | Single Source of Truth，指整个项目只有一个权威的、最新的信息来源 | `Nex2U_Master_Doc_v2.1.md` 是本项目的 SSOT |
| **MECE 原则** | Mutually Exclusive, Collectively Exhaustive，相互独立、完全穷尽，确保分类无重叠、无遗漏 | 营养结构点分类体系的设计原则 |
| **Swagger / Apifox** | API 文档管理工具，用于定义、测试和共享 API 接口 | Node 1 阶段的 API 契约工具 |
| **GitHub** | 代码版本管理平台，也是本项目的 SSOT 文档仓库 | 所有文档和代码的唯一权威存储地 |
| **灰度发布** | 将新版本先开放给少量用户测试，验证稳定后再全量上线的发布策略 | 降低上线风险的关键机制 |
| **并行开发** | 多个开发任务同时进行，互不阻塞，通过 API 契约和 Mock 数据解耦依赖 | 2周内完成 MVP 的核心策略 |
